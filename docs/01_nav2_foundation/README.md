# 01｜Nav2 架构抽象与执行链重建

## 定位

本目录不是基础概念扫盲目录，而是基于已有 Nav2 运行、评估、bag 回放、failure case 和文档沉淀经验，对 Nav2 进行系统级重建的入口模块。

目标不是再回答“planner 是干什么的”这类表层问题，而是逐步回答：

- 一个导航任务从 `NavigateToPose` 发出，到机器人产生控制输出，执行链到底如何运行
- `bt_navigator`、`planner_server`、`controller_server`、`behavior_server` 在运行时如何协作
- action、BT、lifecycle、server、plugin、costmap、TF、localization 在系统中如何耦合
- 参数、配置、插件装载和默认行为之间如何一一对应
- Nav2 为什么是这种架构，而不是另一种

## 为什么这个模块排在最前面

当前已经具备：

- Nav2 基线评估
- 最小对照实验
- 多地图泛化
- bag 回放链路
- failure case 整理
- 文档化与证据链意识

这些能力说明，当前已经具备运行层和验证层的基础。  
最丝滑的下一步，不是立刻硬啃大段源码，而是先把已有经验提升成：

- 架构语言
- 模块边界语言
- 执行链语言
- 配置与插件挂载语言

这个模块就是完成这一步。

## 模块目标

完成本模块后，应逐步具备以下能力：

- 能从 `NavigateToPose` 一路讲到控制输出
- 能说清 BT、action、lifecycle、server、plugin 的运行关系
- 能把概念、节点、包、配置、运行时角色一一对应起来
- 能解释 planner、controller、behavior、costmap、TF、map、localization 的系统位置
- 能以系统设计视角解释 Nav2，而不只是从命令输出或现象角度描述

## 模块主要产物

本模块后续应重点沉淀：

- Nav2 执行链总图
- 核心模块职责与交互图
- server / plugin / BT / action / lifecycle 边界表
- 概念 → 包 → 节点 → 配置 → 运行角色映射表
- 模块总结
- 模块总验收
- 证据索引

## 学习与执行方式

本模块采用 Sprint 机制推进，每个 Sprint 按以下节奏执行：

1. 问题定义与图谱建立  
2. 运行时证据采集  
3. 源码或实现入口深读  
4. 修改、实验或对照  
5. 总结、闭卷与复盘  

每天必须保留：

- 当天核心问题
- 当天资料与证据
- 当天闭卷问答
- 最容易混淆的概念
- 下一步衔接点

## 验收标准

完成本模块时，至少应满足以下条件：

- 能系统口述 Nav2 执行链
- 能清晰区分 server 与 plugin 的职责
- 能说明 costmap、footprint、TF、map、localization 的系统角色
- 能给出概念到源码包的初步映射
- 能通过闭卷问答清晰表达，而不是只会看文档时“感觉懂了”

## 与后续模块的关系

本模块不是终点，而是后续几个方向的入口：

- 为 `02｜ROS2 运行机制与系统行为深潜` 提供系统背景
- 为 `05｜Nav2 源码入口、改造与扩展点` 提供架构地图
- 为后续研究级评测与论文工作提供执行链和模块边界基础
