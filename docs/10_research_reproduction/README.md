# 10｜文献矩阵、baseline 地图、论文复现与 benchmark 建立

## 定位

本目录虽然名称仍为 `research_reproduction`，但实际内容不再只是“跑论文代码”，而是建立一整套研究前置工作流：

- 文献矩阵
- 问题选型
- baseline 地图
- benchmark 设计
- reproducibility protocol
- baseline 复现
- 复现偏差分析
- 自动化复现实验循环

目标不是“我也把别人的代码跑起来了”，而是逐步具备：

- 读一个方向而不是一篇论文的能力
- 选择真正有价值问题的能力
- 识别关键 baseline 的能力
- 把论文方法落到真实机器人系统里的能力
- 用 benchmark 和可复现协议做严谨复现的能力

## 为什么这个模块必须存在

经过前面几个模块，已经具备了：

- 系统架构与运行机制语言
- 实验基础设施
- C++ / rclcpp / pluginlib 门票
- 核心实现与扩展点进入能力
- 研究级评测和实验纪律
- 高级插件与系统定制化能力

这时候再进入复现，才不会是“盲抄代码”。  
而是能真正回答：

- 这篇论文在解决什么问题
- 它和已有 baseline 的关系是什么
- 它在真实系统里应该如何落地
- 为什么复现结果和论文不一致
- 这个工作到底值不值得继续往原创方向推进

## 模块目标

完成本模块后，应逐步具备以下能力：

- 能建立一个方向的文献矩阵，而不是零散摘录
- 能做问题选型，区分真问题和伪问题
- 能画出 baseline 地图，知道哪些比较必须做
- 能建立 benchmark 和指标体系
- 能用 reproducibility protocol 约束实验
- 能复现两类以上 baseline，并分析偏差来源

## 模块主要产物

本模块后续应重点沉淀：

- 文献矩阵
- 问题选型与 baseline 地图
- benchmark / metric 体系
- reproducibility protocol
- baseline A / B 复现记录
- 复现偏差分析报告
- 复现自动化与批量评测脚手架
- 模块总结
- 模块总验收
- 证据索引

## 学习与执行方式

本模块采用 Sprint 机制推进，每个 Sprint 按以下节奏执行：

1. 问题定义与文献 / baseline 图谱建立  
2. 论文、代码、benchmark 证据采集  
3. 论文方法、实验设置、实现骨架深读  
4. baseline 复现、对照、自动化与偏差分析  
5. 总结、闭卷与复盘  

每天必须保留：

- 今天聚焦的是哪个问题 / 哪篇论文 / 哪类 baseline
- 今天收集的关键证据与实验口径
- 今天看到的实现与实验设计要点
- 今天的复现动作或偏差分析动作
- 今天最容易混淆的概念
- 当天闭卷问答
- 明日衔接点

## 验收标准

完成本模块时，至少应满足以下条件：

- 能建立结构化文献矩阵
- 能说明 baseline 选择逻辑
- 能搭出一套可复现 benchmark
- 能复现至少两类 baseline，并对偏差做合理分析
- 能通过闭卷稳定表达“为什么这套复现可信，为什么这个 baseline 必须做”

## 与后续模块的关系

本模块是原创研究工作的直接前置：

- 为 `11｜原创方法、实验叙事与论文管线` 提供问题地图、baseline 地图和实验规范
- 没有这一层，后面的原创方法很容易沦为“我觉得这个想法挺新”
