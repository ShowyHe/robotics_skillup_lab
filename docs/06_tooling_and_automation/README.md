# 06_tooling_and_automation

## 定位

本目录用于把重复执行的检查、启动、评估、整理流程逐步工具化和自动化。

这里不是“随便写几个一键脚本”，而是构建真正有工程价值的工具层。

## 为什么这一层单独存在

自动化不是独立的知识岛，它建立在前面这些东西之上：

- 你知道系统该检查什么
- 你知道启动过程有哪些关键节点
- 你知道结果该记录什么
- 你知道排障流程怎么组织
- 你能用 Python / Shell 把它们串起来

没有这些前提，一键脚本只会把混乱放大。

## 核心目标

逐步形成以下能力：

- 写 healthcheck 工具
- 写一键启动脚本
- 写一键评估脚本
- 写日志收集和归档脚本
- 写结果整理与命名规范工具
- 把高频手工动作沉淀成可复用流程

## 产出标准

工具类内容至少要满足：

- 目的清楚
- 输入清楚
- 输出清楚
- 错误提示清楚
- 能复用，不是一次性脚本

## 建议内容

- 环境检查
- 节点 / topic / action / param 检查
- 一键启动
- 一键回归
- 日志归档
- 结果汇总
- 常见命令包装

## 完成标准

完成本阶段时，应至少做到：

- 能把一类重复任务自动化
- 能解释脚本为什么这样设计
- 能把工具和具体场景对上，而不是为自动化而自动化
- 能明显减少重复劳动和低价值手工操作
