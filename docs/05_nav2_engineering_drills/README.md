# 05｜Nav2 源码入口、改造与扩展点

## 定位

本目录虽然名称仍为 `nav2_engineering_drills`，但实际内容不再只是工程练习，而是正式进入 Nav2 核心实现层的入口模块。

目标不是继续在配置层和现象层打转，而是逐步完成：

- build from source
- 核心包地图建立
- BT / server / plugin / config / action 的源码挂接理解
- 最小源码改造
- 最小插件接入
- 改动与实验验证的绑定

## 为什么这个模块现在出现

经过前面 01–04：

- 已经具备架构视角
- 已经具备运行机制视角
- 已经具备实验基础设施
- 已经具备进入实现层的 C++ 门票

这时候再进入 Nav2 源码，过渡是最丝滑的。  
如果更早进入，很容易被实现细节淹没；如果更晚进入，又会把自己长期困在“会用系统”而不是“会改系统”。

## 模块目标

完成本模块后，应逐步具备以下能力：

- 能面对 `navigation2` 仓库建立包级全景图
- 能找到关键 server、关键插件和关键入口类
- 能解释 BT / server / plugin / config / action 在源码层如何接起来
- 能完成一个最小修改或最小插件接入
- 能把源码改动和实验验证绑在一起，而不是“改了感觉没问题”

## 模块主要产物

本模块后续应重点沉淀：

- Nav2 核心包关系图
- 多个关键包阅读笔记
- BT / server / plugin / config / action 源码挂接说明
- 最小插件骨架理解或最小插件接入记录
- 小范围源码改造记录
- 扩展点总览
- 模块总结
- 模块总验收
- 证据索引

## 学习与执行方式

本模块采用 Sprint 机制推进，每个 Sprint 按以下节奏执行：

1. 问题定义与包级图谱建立  
2. 运行时证据与装配链证据采集  
3. 关键包、关键类、关键接口深读  
4. 最小改造、最小插件接入或小实验  
5. 总结、闭卷与复盘  

每天必须保留：

- 今天进入的是哪个包 / 哪个入口
- 今天看到的装配或调用链证据
- 今天读到的关键类与接口
- 今天的最小改动或实验
- 今天最容易混淆的概念
- 当天闭卷问答
- 明日衔接点

## 验收标准

完成本模块时，至少应满足以下条件：

- 能说清 8–10 个关键包的职责与关系
- 能解释 BT / server / plugin / config / action 在源码层 कैसे接起来
- 能完成一个小修改或最小插件接入
- 能用实验或运行证据验证改动影响
- 能通过闭卷与口述稳定表达自己看到的源码结构与扩展点

## 与后续模块的关系

本模块是很多更高阶能力的入口：

- 为 `06｜评测科学、性能分析与研究实验纪律` 提供“改动后必须验证”的对象
- 为后续 `08｜大代码库阅读方法与架构重建` 提供局部源码阅读经验
- 为后续 `09｜高级插件体系与系统定制化设计` 提供扩展点进入经验
