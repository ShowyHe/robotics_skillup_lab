# LEARNING_RULES — 教学、考试、实验与进度规则

## 1. 核心原则

本课程的主要目标是补齐系统理论，而不是重复已经具备的大量实操经验。

正常学习日默认 **2–3 小时**，优先级为：

```text
理论理解
> 数学 / 公式
> 算法机制
> 源码理解
> 真实工程案例映射
> 闭卷题 / 复测
> 必要实现
> 必要实验
```

实验不是每日必需项，代码也不是每日必需项。

---

## 2. 普通理论 Day 的结构

每个普通 Day 建议包含：

1. 今日目标；
2. 前置知识检查；
3. 不超过 20 个核心知识点；
4. 关键公式与直觉；
5. 必要推导 / 手算；
6. 算法或系统机制；
7. 与真实机器人 / 既有工程经验的对应；
8. 必要源码入口或关键函数；
9. 易错点 / 边界条件；
10. 闭卷题；
11. 通过标准；
12. 今日明确不展开的内容。

不要求为了形式额外加入实验。

---

## 3. 实验规则

只有当实验对能力形成明显增益时才安排。

### 应安排 LAB / PROJECT 的情况

- 理论无法替代真实运行直觉；
- 必须亲手实现才能理解关键数学或机制；
- 新方向此前缺乏任何实践经验；
- 需要验证跨模块闭环；
- 需要形成最终 Capstone 能力。

### 不应安排实验的情况

- 已有真实测试 / 开发经历足以建立案例联系；
- 只是为了证明“今天学过”；
- 环境准备时间远大于知识收益；
- 简单运行 Demo 并不会加深理论理解；
- 普通理论 Day 时间不足以完整完成。

### LAB 独立安排

实验单独放在：

`docs/labs/LABxx_*.md`

复杂实验可占一个或多个完整学习时段，不与普通理论 Day 强行拼接。

---

## 4. 代码 / 最小实现规则

“最小自实现”不是所有算法都必须写。

建议自实现的典型类型：

- A*；
- 简化 KF / EKF；
- PID / LQR；
- 简化 MPC / MPPI；
- Attention；
- 小型 BC / policy；

前提是亲手实现能够显著帮助理解数学、状态、代价、梯度或数据流。

如果已有源码阅读 + 理论推导已经足够，就不为了完成任务强行写代码。

---

## 5. 源码学习规则

### 5.1 已有真实工程对应模块

尤其 Navigation / Control：

```text
真实问题
→ 公司真实实现
→ 反推缺失基础
→ 数学 / 算法本体
→ 官方标准实现
→ 必要时最小自实现
→ 回到真实系统验证
```

默认不主动刷第三、第四套实现。

### 5.2 新方向

Robot Learning / VLM / VLA 等没有公司现成实现时：

```text
论文 / 官方项目
→ 理论
→ 官方实现
→ 必要修改 / 复现
→ 训练或推理验证
```

---

## 6. 已有经验如何使用

已有 ROS2、Nav2、传感器、LIO、Planning、MPPI、真实机器人测试开发经验属于学习资产。

教学时优先采用：

```text
新理论
→ 映射到以前遇到的真实问题
→ 用理论重新解释已有现象
```

而不是：

```text
为了课程完整
→ 再做一次低价值基础实验
```

如果已有工程经验与理论理解不一致，以公式、算法定义、官方实现和真实数据证据重新校准。

## 7. 入门诊断与跳级

每个 Module 开始前允许做入门诊断。

建议判断：

- **≥85% 且核心题正确：** 跳过已掌握部分；
- **70–85%：** 只补薄弱知识；
- **<70% 或核心概念错误：** 完整学习相关部分。

分数只是辅助判断，不能用总分掩盖关键前置错误。

例如工程操作熟练但数学解释不过关，可以跳过操作部分，但理论部分不能跳。

---

## 8. 掌握等级

```text
L1 见过
L2 能解释
L3 能计算 / 推导
L4 能实现 / Debug
L5 能迁移 / 修改 / 设计
```

### 目标

- 基础数学关键知识：至少 L3；
- 核心机器人专业理论：L3→L4；
- 系统 / Navigation / Debug：L4→L5；
- Control关键部分：L4→L5；
- VLA长期主方向：逐步 L4→L5。

---

## 9. 考试规则

普通 Module 的考核可组合：

- 概念题；
- 公式解释；
- 手算 / 推导；
- 数据流 / 架构题；
- 源码阅读题；
- 故障分析题；
- 必要时的小代码题；
- 只有确实需要时才加入实验考核。

核心前置存在明显误解时，不因为 Day 数到了就推进。

非关键小问题可记录进 `PROGRESS.md`，后续复测。

---

## 10. GPT 教学要求

未来 GPT 接手课程时必须：

1. 先读取 `00_GOALS.md`、`03_MASTER_PLAN.md`、`04_MODULE_SPECS.md`、`LEARNING_RULES.md`、`PROGRESS.md`；
2. 不重新询问仓库中已有的学习目标和规则；
3. 讲义理论优先，不擅自增加每日实验；
4. 每日核心知识点不超过 20 个，但单点可以详细讲解；
5. 数学必须连接机器人中的实际变量和物理意义；
6. 重要公式不能只给结论，要说明每一项代表什么；
7. 已有经验优先用于理论案例映射；
8. 不因为用户工程经验强就默认数学也已掌握；
9. 不因为理论暂时陌生就降低毕业标准；
10. 对答错的关键知识进行纠正并安排复测。

```text
Current Module / Day

Weak
Wrong Understanding
Corrected

Foundation Debt
Next
```

`PROGRESS.md` 是跨聊天、跨 GPT 连续教学的唯一当前状态源。

---

## 12. Day / Module / Lesson / LAB 的职责

- `03_MASTER_PLAN.md`：总课程、总 Day 索引；
- `modules/`：Module 内 Day 设计；
- `lessons/`：真正的每日讲义；
- `labs/`：少量必要实验；
- `PROGRESS.md`：当前学习状态。

正式课程设计前不要混淆这些层级。
