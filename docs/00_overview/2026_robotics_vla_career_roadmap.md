# 2026 机器人导航 → 具身智能 / VLA 职业发展路线

## 1. 当前定位

当前阶段不以立即跳槽为主，而是利用现公司真实机器人、传感器、室外场景和完整 ROS2 系统，把已有工程经验做成可验证成果。

当前主线：

```text
代码阅读与 ROS2 核心能力
→ HPA / Nav2 导航系统
→ 无图导航与视觉感知
→ 室外动力闭环
→ 嵌入式与硬件接口排障
→ VLM 语义导航
→ 深度学习、数据工程与模型部署
→ VLA 策略部署、训练与评测
```

目标岗位不是纯 SLAM 后端研究，也不是只会调用模型的应用岗，而是：

> 具备导航、视觉、硬件接口、模型部署、数据闭环和真实机器人验证能力的具身智能 / VLA 系统工程师。

## 3. 阶段一：代码阅读与 ROS2 核心能力

### 3.1 学习目标

不是只会让 AI 解释代码，而是能够独立完成：

- 从入口节点找到完整调用链。
- 判断数据从哪里来、经过哪些类、在哪里改变状态、最终输出什么。
- 修改中等复杂度 ROS2 C++ 代码并完成编译、测试和回归。
- 读懂 Nav2 插件、Action、Lifecycle 和多线程执行逻辑。

### 3.2 重点内容

#### C++

- 类、构造函数、初始化列表。
- 继承、虚函数、接口与多态。
- 引用、指针、智能指针、对象生命周期。
- `vector`、`map`、`unordered_map`、迭代器和算法库。
- lambda、回调、`std::function`。
- 线程、互斥锁、原子变量和异步任务。

#### ROS2

- Node、Publisher、Subscription。
- Service、Client、Action。
- Parameter、Timer、Callback Group、Executor。
- Lifecycle Node。
- TF2、时间戳和坐标系。
- `pluginlib`、动态库导出和 YAML 插件加载。

### 3.3 学习方式

- 工作日每天 45～60 分钟，每周至少 4 天。
- 优先阅读当天正在修改的真实项目代码。
- 每周至少整理一条完整调用链。
- 每周末做一次闭卷复述或小题测试。
- AI 可以辅助解释，但最终必须自己复述并指出关键数据结构和控制条件。

## 4. 阶段二：导航系统形成核心竞争力

### 4.1 HPA

需要完成并理解：

- 起点 S、终点 G 分别搜索附近若干 landmark。
- 使用 JPS 验证 S/G 与 landmark 的真实可达性。
- 将 S、G 和有效边加入本次规划临时 topo 图。
- 边权使用 JPS 路径代价，而不是欧氏距离。
- 禁止跨墙、跨障碍的假直连。
- 不修改预热 landmark 图，不破坏 cache hit 行为。
- 处理图外点、障碍内点、无可达 landmark、局部规划失败等边界情况。
- 建立成功率、耗时、路径正确性和回归测试。

### 4.2 Nav2 运行链

```text
NavigateToPose
→ BT Navigator
→ planner_server
→ Planner Plugin（如 SmacPlannerHybrid / Hybrid-A*）
→ global path
→ controller_server
→ Controller Plugin（如 MPPI）
→ local costmap + path + robot state
→ cmd_vel
→ 底盘执行
```

需要掌握：

- `planner_server` 如何加载和调用全局规划插件。
- `controller_server` 如何周期性调用控制插件。
- Hybrid-A* 如何考虑运动学约束并生成路径。
- MPPI 如何利用路径、机器人状态和局部代价地图输出速度。
- Costmap 只表达环境代价，真正的避障决策由 Controller 完成。
- Planner、Controller、Behavior、BT、Lifecycle 之间如何协作。

当前不要求独立重写 MPPI，但必须能解释其接入链路、输入输出、关键参数和失败模式。

## 5. 阶段三：无图导航与视觉感知

### 5.1 无图导航

完成：

- GPS 可靠性门控。
- 高德导航步骤解析与任务状态机。
- 人行道、盲道、路口、公交站和过街逻辑。
- 红绿灯与斑马线识别接入。
- TTS 优先级、合并、节流和过期处理。
- 识别丢失、GPS 失效、超时、人工接管和安全停止。
- rosbag 离线回放、现场测试、问题复现和回归。

### 5.2 视觉能力

优先学习真实机器人需要的部分：

- 相机模型、内参、外参、畸变和标定。
- OpenCV 图像处理。
- YOLO 检测、分割和跟踪。
- 红绿灯颜色连续确认与时序稳定。
- 斑马线、人行道、盲道的连续帧确认和丢失处理。
- 像素坐标 → 相机坐标 → `base_link` → `map`。
- 不同距离、角度、曝光、遮挡、天气和运动模糊评测。

目标不是只看 mAP，而是建立机器人可用性指标：

- 误检率。
- 漏检率。
- 首次稳定识别距离。
- 连续帧稳定性。
- 状态切换错误率。
- 实机任务成功率。

## 6. 阶段四：室外动力、定位与局部避障

第一版动力闭环不依赖大模型：

```text
GPS + IMU + 里程计
→ 定位与坐标转换
→ 高德 / HPA 产生目标或航点
→ Nav2 规划
→ 雷达 / ToF 写入 local costmap
→ MPPI 计算 cmd_vel
→ 仲裁与底盘接口
→ 机器人执行
```

重点解决：

- GPS 经纬度如何转换为导航坐标。
- `map → odom → base_link` TF 链是否稳定。
- 无完整静态地图时，全局目标和局部规划如何衔接。
- 雷达、ToF 的坐标、时间戳、QoS 和障碍阈值。
- local costmap 如何表达机器人周围障碍。
- MPPI 如何读取路径和局部代价地图。
- GPS 漂移、传感器失效、控制超时、急停和人工接管。
- 先空旷、低速、短距离，再逐步增加复杂场景。

## 7. 阶段五：嵌入式与硬件接口

不需要转型为嵌入式工程师，但需要具备完整系统排障能力。

### 7.1 CAN 与串口

需要掌握：

- CAN ID、标准帧、扩展帧、DLC、数据字节和大小端。
- 波特率、终端电阻、错误帧和 bus-off。
- `ip link`、`candump`、`cansend`。
- 串口设备、波特率、原始数据、协议帧和校验。
- 根据协议文档解析底盘状态、控制指令和传感器数据。
- 判断问题位于 ROS、Linux 驱动、CAN/串口、MCU 还是执行器。

### 7.2 MCU 基础

需要理解：

- MCU、固件、驱动、中断、定时器、DMA、看门狗。
- 传感器采集、执行器控制和通信链路。
- 实时系统与 Linux 上层程序的区别。
- 能阅读简单接口和协议，不要求现阶段独立开发完整 STM32 工程。

### 7.3 排障目标

能够沿完整链路定位：

```text
导航是否产生 cmd_vel
→ 仲裁节点是否放行
→ Linux 驱动是否发送控制帧
→ CAN / 串口数据是否正确
→ MCU 是否响应
→ 电机 / 底盘是否执行
→ 状态反馈是否回到 ROS2
```

动力开发前后每周安排 1～2 小时，结合真实底盘问题学习。

## 8. 阶段六：VLM 语义导航接入

优先采用服务器部署千问视觉模型，机器人端运行轻量客户端。

```text
相机关键帧
+ 当前任务
+ GPS / 高德步骤
+ YOLO / OCR 结果
+ 机器人状态
→ ROS2 VLM Client
→ 服务器 Qwen-VL
→ 固定 JSON
→ Skill Dispatcher
→ HPA / Nav2 / outdoor_nav
```

VLM 负责：

- 场景理解。
- 任务语义判断。
- Skill 选择。
- 目标或航点建议。

VLM 不直接发布 `/cmd_vel`。

必须具备：

- Skill 白名单。
- JSON Schema 校验。
- 超时、断网和非法输出降级。
- 相同决策连续确认。
- 图片压缩、关键帧选择和调用频率限制。
- 内存、网络延迟和服务器负载监控。
- 大模型失效时，定位、避障和停车仍然有效。

## 9. 阶段七：SLAM 基础

SLAM 不是当前第一优先级，但需要补到“能选方案、能部署、能排障”的程度。

需要理解：

- 地图、定位、漂移和回环。
- ICP、PnP 分别解决什么问题。
- 激光、视觉、IMU 和里程计如何提供约束。
- Cartographer、RTAB-Map、LIO-SAM、FAST-LIO、VINS-Fusion 的适用场景。
- 定位失效时导航系统如何降级。

暂时不以纯 SLAM 后端、IMU 预积分或因子图源码研发为主线。

---

## 10. 阶段八：深度学习、数据工程与模型部署

在导航、视觉和动力闭环稳定后，系统补充：

- Python、NumPy、PyTorch。
- Transformer、视觉编码器和多模态基础。
- 数据集划分、损失函数、训练、验证、过拟合和数据增强。
- CUDA、TensorRT、量化和显存/内存优化。
- 图像、语言、机器人状态和动作的时间同步。
- 数据采集、清洗、标注、回放和版本管理。

目标是具备模型部署与评测能力，而不是只会调用 API。

## 11. 阶段九：VLA 与机器人学习

VLA 完整闭环：

```text
视觉 + 语言 + 机器人状态
→ VLA 策略
→ 动作序列
→ 安全控制层
→ 执行器
→ 结果与轨迹回收
→ 数据清洗
→ 训练和迭代
```

需要逐步学习：

- 模仿学习与行为克隆。
- Diffusion Policy。
- 动作分块、时序建模和多模态对齐。
- 强化学习基础。
- 遥操作数据采集。
- Gazebo、Isaac Sim 或 MuJoCo。
- Sim2Real、真实机器人评测和安全约束。

VLA 放在导航、视觉、动力、数据和部署能力之后，避免只懂模型、不懂机器人闭环。
