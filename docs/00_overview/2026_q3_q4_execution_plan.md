# 2026 Q3–Q4 机器人导航与 VLM 执行计划

## 1. 阶段目标

从 2026 年 7 月中旬到 11 月初，围绕现有真实机器人项目完成：

1. HPA S/G 接入收尾。
2. 无图导航和红绿灯、斑马线视觉收尾。
3. HPA、ToF、GPS、视觉、TTS 的无动力联合测试。
4. 室外动力闭环开发。
5. GPS 导航、local costmap 和 MPPI 避障联调。
6. CAN、串口和 MCU 链路排障能力建立。
7. 在底层导航稳定后接入服务器千问 VLM。
8. 形成架构文档、测试报告、演示视频和简历证据。

## 3. 7 月 17 日：HPA S/G 接入收尾

### 3.1 开发内容

- 起点 S、终点 G 分别查找附近若干 landmark。
- 使用 JPS 计算 S/G 到候选 landmark 的真实可达路径。
- 只对 JPS 可达的候选建立边。
- 边权采用 JPS 路径代价。
- 将 S、G 和有效边加入本次 `plan()` 的临时 topo 图。
- 保持预热 landmark 图和 cache 行为不变。
- 删除欧氏假直连和无约束全图 fallback。

### 3.2 验收条件

- 正常 S/G 能生成正确拓扑路径。
- 障碍隔离的候选 landmark 不建边。
- 不出现跨墙、跨障碍捷径。
- S/G 无可达接入点时明确失败，不伪造路径。
- 单次 `plan()` 增量耗时满足既定目标。
- 保存测试输入、地图、输出路径和耗时结果。

### 3.3 可能遗留

后续测试仍可能暴露：

- 候选数量不足。
- 地图边界点接入失败。
- JPS 局部路径长度和 topo 边权口径问题。
- 临时节点清理或重复 ID 问题。

这些属于测试阶段修正，不再改变主体架构。

## 4. 7 月 20 日—8 月 2 日：无图导航收尾与视觉训练

## 4.1 无图导航收尾

- 梳理完整状态机。
- 修复红绿灯状态切换。
- 修复斑马线识别、进入、通过和丢失逻辑。
- 检查盲道连续帧确认和丢失计数清零。
- 检查过街超时后的安全状态。
- 检查 GPS 可靠性门控。
- 检查 TTS 优先级、节流、合并和过期。
- 完成不带动力的全流程联调。

## 4.2 红绿灯与斑马线视觉训练

### 数据

- 不同距离。
- 不同观察角度。
- 阴天、晴天、逆光、阴影。
- 遮挡和小目标。
- 红绿灯曝光、反光和颜色混淆。
- 不同样式、磨损和局部遮挡的斑马线。

### 训练与验证

- 完成首轮训练。
- 统计分类别误检、漏检。
- 保存典型错误样本。
- 加入连续帧确认和状态去抖。
- 不只看 mAP，验证在状态机中的真实效果。

## 4.3 阶段验收

- 无动力全流程能连续运行。
- 状态机不存在明显错误推进。
- 红绿灯和斑马线形成可现场测试版本。
- 视觉丢失、低置信度和超时都有确定行为。
- 形成待测场景表和已知问题表。

## 5. 8 月 3 日—8 月 31 日：无动力联合测试与修改

## 5.1 测试范围

- HPA 路径正确性和性能。
- 无图导航任务状态机。
- 红绿灯、斑马线、人行道和盲道视觉。
- GPS 可靠性和遮挡场景。
- ToF、雷达障碍数据。
- TTS 事件优先级。
- 节点启动、Lifecycle、DDS 和资源占用。
- CPU、内存、时延和进程异常。

## 5.2 标准流程

```text
发现问题
→ 保存 rosbag、日志、配置和版本
→ 提出可验证假设
→ 单变量修改
→ 同场景复测
→ 指标对比
→ 回归旧场景
→ 记录结论与限制
```

## 5.3 建议测试维度

### HPA

- 不同 S/G 位置。
- 地图边缘、障碍附近和狭窄通道。
- cache hit / miss。
- 无可达接入点。
- 规划耗时和路径长度。

### 视觉和状态机

- 识别连续稳定。
- 短时丢失。
- 错误识别。
- 多目标冲突。
- 状态超时。
- 识别恢复后的状态衔接。

### ToF 和障碍

- 地面误打点。
- 不同行传感器信号阈值。
- 障碍点是否进入 costmap 输入链。
- 时间戳、坐标系、QoS 和数据频率。

## 5.4 8 月底验收

- HPA 主体问题关闭。
- 无图导航进入稳定测试版本。
- 视觉具备可测指标和错误样本库。
- ToF、GPS、TTS 和状态机联合运行无明显致命问题。
- 有完整测试清单、问题清单和版本冻结点。

## 6. 9 月 1 日—9 月 30 日：室外动力闭环开发

## 6.1 第一阶段：控制链确认

- 确认最终底盘速度入口。
- 梳理 `/cmd_vel` 到仲裁节点、控制模式和底盘驱动的完整链路。
- 设置最大线速度、角速度、加速度和急停。
- 空旷区域、短距离、低速测试。

完整链路：

```text
Nav2 / outdoor_nav
→ cmd_vel
→ 速度平滑或仲裁
→ 底盘驱动
→ CAN / 串口
→ MCU
→ 电机 / 四足控制器
```

## 6.2 第二阶段：GPS 定位与航点

- 接入 GPS、IMU 和里程计。
- 明确经纬度到导航坐标的转换方式。
- 验证 `map → odom → base_link` TF 链。
- 检查位置跳变、朝向和漂移。
- 高德或 HPA 输出分段目标 / 航点。
- Nav2 负责到达短距离目标。

## 6.3 第三阶段：local costmap 与 MPPI

- 雷达、ToF 数据写入 local costmap。
- 验证 frame、时间戳、观测源和障碍阈值。
- 验证 MPPI 读取 global/local path、机器人状态和 local costmap。
- 测试静态障碍、动态障碍、窄路、停车和恢复。

需要能解释：

```text
planner_server
→ Hybrid-A* / Smac Planner Plugin
→ Path
→ controller_server
→ MPPI Plugin
→ local costmap + Path
→ cmd_vel
```

## 6.4 第四阶段：嵌入式与硬件排障

同步学习并验证：

- ROS 是否产生速度。
- 仲裁是否放行。
- Linux 驱动是否发出正确 CAN / 串口数据。
- CAN ID、DLC、大小端和协议字段是否正确。
- MCU 是否收到并执行。
- 底盘状态是否反馈到 ROS2。
- bus-off、串口占用、超时和看门狗行为。

不要求独立开发完整单片机固件，但必须能定位故障所在层级。

## 6.5 9 月底验收

- 不依赖大模型完成低速动力闭环。
- GPS 目标、Nav2 规划、local costmap、MPPI 和底盘贯通。
- 有急停、限速、人工接管和失效保护。
- 能解释 Hybrid-A* 与 MPPI 的 Nav2 插件接入链路。
- 能完成基本 CAN / 串口 / MCU 排障。

## 7. 10 月 1 日—10 月 31 日：动力测试与 VLM 接入

## 7.1 前置条件

VLM 不是动力闭环的前置条件。只有以下链路稳定后才接入：

- GPS 与 TF 基本稳定。
- Nav2 能执行航点。
- local costmap 能表达障碍。
- MPPI 能低速避障。
- 急停和失效保护有效。

## 7.2 动力联合测试

覆盖：

- 空旷直行。
- 转弯和分段航点。
- 静态与动态障碍。
- 红绿灯等待。
- 斑马线进入和通过。
- GPS 漂移和短时失效。
- 视觉误检、漏检和丢失。
- 网络断开和节点异常。

## 7.3 千问 VLM 接入

架构：

```text
相机关键帧 + 任务 + GPS 步骤 + YOLO/OCR + 机器人状态
→ ROS2 VLM Client
→ 服务器 Qwen-VL
→ 固定 JSON
→ Skill Dispatcher
→ outdoor_nav / HPA / Nav2
```

安全要求：

- VLM 只输出高层 Skill 或目标建议。
- 不直接输出 `/cmd_vel`。
- 固定 JSON Schema。
- Skill 白名单。
- 超时、断网、非法输出时安全降级。
- 图片压缩和低频关键帧调用。
- 记录输入、输出、延迟、内存和执行结果。

## 7.4 10 月底验收

- 室外动力系统经过多轮场景回归。
- VLM 接入不破坏底层导航和安全逻辑。
- 断网或服务器异常时机器人仍能停车或保持确定性流程。
- 有 VLM 判断正确率、延迟和失败案例记录。

## 10. 风险与调整原则

### 风险

- 红绿灯和斑马线在复杂光照下训练周期可能超出两周。
- GPS 室外定位精度和朝向可能成为动力闭环主要瓶颈。
- local costmap、TF、时间戳和控制仲裁可能暴露历史问题。
- VLM 服务器延迟、网络和内存问题可能影响使用体验。

### 调整原则

- 优先保证安全和确定性闭环。
- 不为了赶时间把 VLM 放到底层控制链。
- 不同时扩展 SLAM、VLA 训练和复杂深度学习。
- 每次只修改一个主要变量并保存证据。
- 若动力闭环延期，VLM 顺延，不牺牲底层稳定性。

当前最重要的交付仍然是：

> HPA + 无图导航 + 视觉 + GPS + local costmap + MPPI + 安全动力闭环。
