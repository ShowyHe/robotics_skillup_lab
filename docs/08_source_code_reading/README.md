# 08｜大代码库阅读方法与架构重建

## 定位

本目录虽然名称仍为 `source_code_reading`，但实际内容不再是“读一点源码”这样的局部活动，而是训练面对大型机器人软件仓库时的整体理解能力。

目标不是“会看某个文件”，而是逐步具备：

- 大型仓库阅读策略
- 模块地图建立能力
- 调用链重建能力
- 接口与扩展点识别能力
- 从 implementation 反推 architecture 的能力
- 从代码风格、依赖方向和实现细节中看出设计权衡的能力

## 为什么这个模块必须存在

前面已经进入过：

- Nav2 关键包入口
- BT、server、plugin、config 挂接
- 最小改造 / 最小插件接入
- 一些局部包级阅读

这说明已经不缺“敢打开源码”的勇气。  
真正缺的是：

> **如何面对一个真正大的代码库，而不迷路，不被细节淹没，不把一堆文件误以为理解了系统。**

如果不专门补这个模块，后面会出现两个典型问题：

- 读得越来越多，但理解越来越碎
- 能追一个类、一个函数，但建立不了系统级设计图

## 模块目标

完成本模块后，应逐步具备以下能力：

- 能快速建立仓库全景图、模块地图和依赖方向图
- 能从入口定位关键调用链
- 能识别哪些是核心接口，哪些只是实现细节
- 能从实现细节反推出设计意图
- 能开始评价设计，而不是只复述设计

## 模块主要产物

本模块后续应重点沉淀：

- 大代码库阅读方法论
- 模块依赖图
- 关键调用链重建图
- architecture reconstruction notes
- 关键类族谱图
- 设计权衡分析页
- 模块总结
- 模块总验收
- 证据索引

## 学习与执行方式

本模块采用 Sprint 机制推进，每个 Sprint 按以下节奏执行：

1. 问题定义与仓库图谱建立  
2. 入口、依赖、调用证据采集  
3. 接口、抽象类、关键实现深读  
4. 调用链重建、依赖分析或设计对照  
5. 总结、闭卷与复盘  

每天必须保留：

- 今天进入的是哪个仓库层次
- 今天识别出的关键模块 / 类 / 接口 / 调用链
- 今天从实现中看出的设计意图
- 今天最容易混淆的概念
- 当天闭卷问答
- 明日衔接点

## 验收标准

完成本模块时，至少应满足以下条件：

- 面对一个大型仓库，能快速建立全景图
- 能从入口追到关键调用链，而不是只盯着一个类
- 能识别模块边界和依赖方向
- 能从代码实现反推出架构意图
- 能开始评价设计权衡，而不是只会“看懂了”
- 能通过闭卷稳定表达自己的阅读方法与判断

## 与后续模块的关系

本模块是后面高阶扩展和研究工作的关键支点：

- 为 `09｜高级插件体系与系统定制化设计` 提供系统级架构感
- 为 `10｜文献矩阵、baseline 地图、论文复现与 benchmark 建立` 提供“如何把论文实现放进大系统”的理解能力
- 为 `11｜原创方法、实验叙事与论文管线` 提供“系统设计级思维”而不是“局部 patch 思维”
