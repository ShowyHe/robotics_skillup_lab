## Part A — Foundation（基础层）

### 1. MPC 的基本思路

与只规定 \(u=-Kx\) 的反馈形式不同，MPC 在每个控制周期求一段未来控制序列。候选输入经系统预测模型得到未来状态，优化器比较控制效果与代价，必须满足明确规定的硬约束。

核心环节：**预测 → 优化 → 执行第一步 → 反馈 → 重新优化**。求出的预测序列不是实际世界已经发生的运动，也不是要一次性开环执行的整段指令。

### 2. 预测模型与状态定义

统一写为：

\[
x_{k+1}=f(x_k,u_k)
\]

若采用线性离散模型，\(f(x,u)=Ax+Bu\)，其中 \(x\in\mathbb R^n,\ u\in\mathbb R^m,\ A\in\mathbb R^{n\times n},B\in\mathbb R^{n\times m}\)。

状态可包含位置（m）、航向（rad）、线速度（m/s）、角速度（rad/s）；必须明确坐标系和角度约定。输入可能是目标速度，也可能是加速度/力矩，不能混为一谈。这里使用的 \(\Delta t\) 单位为秒，改变采样时间后应更新离散动力学参数。

### 3. 预测序列符号（Prediction Sequence）

在**当前时刻 k** 定义预测初态：

\[
x_{0|k}=\hat x_k
\]

优化的未来输入：

\[
U_k=[u_{0|k},u_{1|k},\ldots,u_{N-1|k}]
\]

递推状态：

\[
x_{i+1|k}=f(x_{i|k},u_{i|k}),\quad i=0,\ldots,N-1
\]

因此有 N 个控制输入和 N+1 个预测状态。\(x_{i|k}\) 是“**在 k 时刻**对第 i 个未来步的预测”，不等于未来实测状态 \(x_{k+i}\)。

### 4. N、dt 与 T（Hard Gate）

预测步数 \(N\) 无量纲，预测步长 \(\Delta t\) 单位 s，预测时域：

\[
\boxed{T=N\Delta t}
\]

若 \(N=60,\ \Delta t=0.05\,\mathrm{s}\)，则 \(T=3\,\mathrm{s}\)。

注意：每周期优化未来 3 s，并不等于将一条控制命令持续执行 3 s。实际控制器更新周期也不一定与预测 \(\Delta t\) 完全相同，必须按具体实现核实。

### 5. 参考轨迹如何进入 MPC？

参考序列定义为：

\[
r_{0|k},r_{1|k},\ldots,r_{N|k}
\]

每步状态偏差：

\[
e_{i|k}=x_{i|k}-r_{i|k}
\]

几何 path 只有空间位置/形状，不一定包含每一时刻应到哪里；要用作时间参考时，需明确参数化、目标状态或前视选点规则。对于航向误差，必须声明 frame、角度差和 wrap 规则，不能直接把不同坐标系的角度相减。

### 6. 阶段代价（Stage Cost）

一个教学用的二次型阶段代价：

\[
\ell_i=e_{i|k}^TQe_{i|k}
+(u_{i|k}-u^{\rm ref}_{i|k})^TR(u_{i|k}-u^{\rm ref}_{i|k})
\]

这里 \(Q\succeq0,R\succ0\)，维度分别 \(n\times n,m\times m\)。第一项惩罚偏离参考，第二项惩罚控制输入相对参考的变化。权重应考虑变量单位与归一化。没有控制参考时可令 \(u^{\rm ref}=0\)。

阶段代价可以增加舒适度、输入平滑等项，但不应该把所有安全约束只用有限代价替代。

### 7. 终端代价（Terminal Cost）

常见终端项：

\[
\ell_f=e_{N|k}^TQ_fe_{N|k}
\]

其中 \(Q_f\succeq0\)。它惩罚预测时域末端偏差，避免优化器只看眼前而忽略末端质量。**终端代价不是硬性的“必须到达终点”条件**。硬终端约束必须另行写出来。

### 8. MPC 的完整数学问题（Hard Gate）

一种有限时域 MPC：

\[
\boxed{
\begin{aligned}
\min_{\{u_{i|k}\}_{i=0}^{N-1}}\quad&
\sum_{i=0}^{N-1}\Big[
e_{i|k}^TQe_{i|k}+
(u_{i|k}-u_{i|k}^{\rm ref})^TR(u_{i|k}-u_{i|k}^{\rm ref})
\Big]+e_{N|k}^TQ_fe_{N|k}\\
\mathrm{s.t.}\quad&
x_{0|k}=\hat x_k,\\
&x_{i+1|k}=f(x_{i|k},u_{i|k}),\\
&x_{i|k}\in\mathcal X,\quad u_{i|k}\in\mathcal U.
\end{aligned}}
\]

\(\mathcal X\) 是允许状态集合，\(\mathcal U\) 是允许输入集合。使用时须写清楚各约束作用于哪些预测步及终态；不应默认一个不等式已经约束了全部物理行为。

### 9. 输入幅值约束：速度与转向

若模型输入选择 \(u_i=[v_{\rm cmd,i},\omega_{\rm cmd,i}]^T\)，可限制：

\[
|v_{\rm cmd,i}|\le v_{\max},\qquad
|\omega_{\rm cmd,i}|\le\omega_{\max}
\]

前者单位 m/s，后者 rad/s。对差速机器人，转向可用角速度/曲率约束表达；对真正的汽车式转向机构，才会直接使用前轮转角 \(\delta\) 限制。不同机器人不能直接混用。

命令速度受限，不自动证明真实车身速度或碰撞行为已受相同限制。

### 10. 加速度 / 转向变化约束

当控制输入表示**速度命令**时，可用命令变化率界：

\[
|v_{\rm cmd,i}-v_{\rm cmd,i-1}|\le a_{\max}\Delta t
\]

\[
|\omega_{\rm cmd,i}-\omega_{\rm cmd,i-1}|\le\alpha_{\max}\Delta t
\]

\(a_{\max}\) 为 m/s²，\(\alpha_{\max}\) 为 rad/s²。首步应与上次已发指令比较，不能凭空认为上次指令等于0。

此约束只保证**命令变化幅度**；若要保证真实加速度，模型/状态约束还必须描述执行器响应。

### 11. 状态约束与障碍物

可要求预测状态满足：实际速度或关节速度范围、关节位置限制、运动姿态限制、机器人足迹与障碍不发生碰撞等。

足迹碰撞检查必须明确机器人几何、障碍地图、坐标系及预测时刻。障碍物的中心点距离不足以替代足迹几何，动态障碍的运动也不能当作已知确定值。

### 12. 硬约束与软代价的差别（Hard Gate）

硬约束如 \(g(x,u)\le0\)：不满足的候选控制序列是**不可行**的。

软惩罚如 \(\rho[\max(0,g(x,u))]^2\)：违反会让代价增加，但仍有可能被接受。

所以“很高的碰撞代价”不一定等于“数学上禁止碰撞”。安全急停等机制需独立验证；不能声称 MPC 形式本身已经保证真实机器人安全。

## Part B — Core Theory（核心理论层）

### 13. Receding Horizon（滚动时域）（Hard Gate）

每一周期执行：

1. 从状态估计和新观测获得 \(\hat x_k\)。
2. 根据当前参考、预测模型与约束，优化未来 N 步的输入序列。
3. 在通过必要的安全检查后，只发送/执行最优序列的第一步 \(u_{0|k}^\star\)。
4. 下一个周期重新取得状态 \(\hat x_{k+1}\)。
5. 窗口向前滚动，重新求最优控制序列。

核心区别：**预测 N 步，通常只实施一步**。这样才能持续修正模型误差、动态障碍和反馈变化。

### 14. 为什么不能一次执行整段序列？

如果把 N 步完全开环执行，之后真实运动与预测存在差异，或者道路出现新障碍，后面的指令仍可能照旧执行。滚动时域通过反复反馈/重规划降低这一问题，但传感器失效、控制超时或底盘命令被忽略时，它也不能自动保证安全。

### 15. Horizon / dt 手算

若 \(N=40,\Delta t=0.05\) s，则 T=2 s。

若 N 仍为40、\(\Delta t=0.10\) s，则 T=4 s，但离散时间更粗；必须重新核对 A/B 或 f、参考、障碍采样和约束中的 \(\Delta t\)。

若 N=80、\(\Delta t=0.05\) s，也有 T=4 s，但预测/优化步数更多，时间分辨率不同，计算负担可能增大。

### 16. 预测时域与计算负担的权衡（L4）

- 固定 dt 增加 N：预测更远，优化变量及 rollout 计算一般增加。
- 固定 N 增加 dt：覆盖更久，时间分辨率降低，可能忽略短时快速变化。
- 固定 T 减小 dt：N 变大，预测精细程度可能提高，但计算量也可能上升。
- T 太短：看不到远处转弯、障碍或约束。
- T 太长：环境预测不确定、模型误差积累，也可能超出实时预算。

没有脱离场景和模型的“越长越好”，必须按速度、障碍变化、平台算力与控制延迟验证。

### 17. Feasibility（可行性）与最优性（Hard Gate）

**可行**：存在至少一组 N 步输入，在预测模型中同时满足初态、动力学以及所有硬约束。

**最优**：在可行集合内找到目标函数最小的候选（前提是所用算法确有相应最优性保证）。

如果参考终点仅写进软代价，达不到参考未必意味着不可行；如果另写硬约束“第 N 步必须到达”，则有可能导致无解。不可行也不一定是求解器坏了。

### 18. 手算：两步内能到目标吗？

理想一维模型：

\[
p_{i+1}=p_i+v_i\Delta t,\quad p_0=0
\]

取 \(N=2,\ \Delta t=1\) s、\(0\le v_i\le0.5\) m/s。最大可达位移：

\[
p_2\le2(0.5)(1)=1.0\,\mathrm m
\]

若要求**硬终端** \(p_2=2\) m，问题不可行；如果只用终端代价惩罚 \((p_2-2)^2\)，仍有合法输入，只是无法消除所有终端误差。

该数值结论仅适用于题设直接控制速度的理想模型，真实机器人还需加速度/障碍/执行器约束。

### 19. 手算：限幅如何改变最优输入？

教学模型 \(p_1=p_0+u_0\Delta t\)，\(p_0=0\) m、\(\Delta t=1\) s，\(u_0\) 是速度（m/s），目标位置1.2 m；假设代价中位置与速度按1 m、1 m/s归一化：

\[
J=(u_0-1.2)^2+0.1u_0^2
\]

\[
\frac{dJ}{du_0}=2.2u_0-2.4
\]

所以无约束最优 \(u_0=12/11\approx1.091\) m/s。

若硬约束 \(0\le u_0\le0.5\) m/s，区间内 J 随 u 增大而降低，故受约束最优是 \(u_0^\star=0.5\) m/s。

在这个**标量凸例子**中，裁剪无约束答案恰好得到受约束最优；在多维、多步、含耦合约束的问题中，逐项裁剪通常不保证整段解仍最优或可行。

### 20. Warm Start（热启动）

把上次求解的最优输入序列向前挪一步，作为下一次求解初始猜测：

\[
[u_{1|k}^\star,\ldots,u_{N-1|k}^\star,u_{\rm tail}]
\]

尾部输入按设计补齐。热启动有机会减少搜索/优化负担，但不保证一定更快、更优、更可行。**出现新障碍、更新硬约束或状态偏离后，旧序列必须重新检查**，不能未经确认就直接执行剩余控制指令。

### 21. MPC 与 LQR（Day83 复用）

| 问题 | 经典无约束无限时域 LQR | 典型受约束 MPC |
|---|---|---|
| 控制形式 | 可由 Riccati 得到固定反馈 \(u=-Kx\) | 每周期在线求 N 步、执行第一步 |
| 目标 | 长期二次型代价 | 有限时域 stage / terminal cost |
| 硬约束 | 不天然处理幅值/碰撞硬约束 | 可显式将硬约束纳入优化 |
| 实时计算 | 稳态 K 通常离线求解 | 持续在线优化，需考虑超时 |
| 安全 | 不因代价最优就自动安全 | 不因可写硬约束就保证实机安全 |

在无约束线性二次型特殊情形下，有限时域 LQR 与 MPC 形式可直接对应；MPC 的特点是持续滚动重新求解，并可表达更丰富的约束。

### 22. 求解失败与可行性边界

常见失败原因：速度/加速度约束过严、硬终端过近、初始状态已违约束、动态障碍改变可行通道、模型/参考不一致、优化预算耗尽等。

应先检查模型、当前状态、参考、约束和计算时间，再区分“数学上无可行序列”和“有可行序列但实际求解未找到”。不能把 INFEASIBLE 标签自动当成源码缺陷或必然无路可走。

## Part C — Advanced / Owner（工程层）

### 23. 局部导航映射：路径并不等于 MPC 参考轨迹

导航中的 global/local path 通常描述几何路线；MPC 的 \(r_{i|k}\) 是每个预测时刻的目标状态。将 path 映射到参考序列时需定义进度、前视/速度或时间参数化方式。

另外单独核对：footprint、局部障碍图及坐标系；输入是速度命令还是加速度；动态障碍预测；哪些是 cost、哪些是 hard constraint。路径本身不压障碍也无法直接证明控制序列可行。

### 24. Manipulation（机械臂轨迹）映射

机械臂可以定义状态 \(x=[q^T,\dot q^T]^T\)，q 为关节位置（rad）、\(\dot q\) 为关节速度（rad/s）；控制输入可按所选模型设为力矩（N·m）或关节加速度（rad/s²），不可混用。

参考序列包括关节位置/速度目标；约束可包含关节位置、速度、加速度、力矩、障碍碰撞。滚动优化的结构与局部导航相似，但动力学和物理限制不同。

### 25. Owner 排障与安全边界

当局部控制走偏、无法前进或频繁失效，优先建立证据链：

1. 状态/时间：真实反馈与 \(\hat x_k\)、timestamp、frame、传感器延迟。
2. 模型：f 或 A/B、输入单位、\(\Delta t\)、实际执行器响应。
3. 参考：每步 \(r_{i|k}\) 是否来自有效路径和正确时间/进度。
4. 代价：stage/terminal 各分项及权重 Q/R。
5. 约束：逐步验证速度/加速度/转向限制、footprint 和碰撞硬约束。
6. 求解：是否存在合法序列、超时/不可行原因、Warm Start 是否经新约束验证。
7. 实际执行：第一步是否被限幅、底盘是否响应、反馈是否及时。
8. 安全降级：优化失败时如何停车或请求重规划；不能把重复执行上一条序列默认为安全。

MPPI 也可借助 MPC 的预测时域/代价/滚动优化概念理解，但不同实现的采样、碰撞处理和输入限制必须查对应源码与日志，不能仅凭课程框架推定实际程序行为。本日不讲 QP/NMPC 求解器细节。
