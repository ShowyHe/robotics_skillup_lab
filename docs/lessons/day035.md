## 1. Semantic Segmentation（语义分割）

Semantic Segmentation 对每个 Pixel（像素）预测类别。

例如：

\[
road,\ grass,\ person,\ wall,\ sky
\]

最终得到：

\[
\boxed{
H\times W
}
\]

的 Semantic Mask（语义掩码）。

---

## 2. Semantic vs Instance Segmentation

Semantic Segmentation：

\[
\boxed{
\text{每个 Pixel 属于什么类别}
}
\]

例如图中两个人的 Pixel 都是 person。

Instance Segmentation（实例分割）：

\[
\boxed{
\text{每个 Pixel 属于哪个具体实例}
}
\]

例如：

- person #1
- person #2

因此 Instance Segmentation 不只区分类别，还区分同类别的不同对象。

---

## 3. Pixel Logit / Pixel Class

若有 \(C\) 个类别，模型可对每个 Pixel 输出 \(C\) 个 Logit（原始分类分数）。

输出 Tensor（张量）通常：

\[
\boxed{
C\times H\times W
}
\]

每个 Pixel 对各类别都有分数，最终可通过 Softmax / Argmax 得到 Pixel Class（像素类别）。

因此可以把 Semantic Segmentation 理解成：

\[
\boxed{
\text{对每个 Pixel 做一次 Classification（分类）}
}
\]

---

## 4. Class Imbalance（类别不平衡）

若一张图中 99% 是 road、1% 是 person，而模型全部预测为 road：

\[
Accuracy=99\%
\]

但：

\[
person\ Recall=0
\]

因此：

\[
\boxed{
Pixel\ Accuracy\ 高
\neq
机器人任务表现好
}
\]

训练时可能通过类别权重、采样、数据补充或不同 Loss 设计改善。

---

## 5. Boundary Error（边界误差）

Segmentation 边界错误可能只涉及少量 Pixel，却会直接影响机器人安全边界。

例如：
- 行人脚边缘
- 路沿
- 台阶
- 墙边
- 盲道边缘

因此：

\[
\boxed{
Pixel\ Metric\ 好
\neq
安全边界一定可靠
}
\]

---

## 6. Traversability（可通行性）

Traversability 回答：

\[
\boxed{
\text{机器人能不能安全通过}
}
\]

它不是简单 Semantic Class（语义类别）。

即使模型判断：

\[
road
\]

也可能存在：
- 行人
- 施工障碍
- 坑
- 台阶
- 坎
- 大坡度

因此：

\[
\boxed{
Semantic\neq Geometry
}
\]

并且：

\[
\boxed{
Semantic\neq Traversability
}
\]

可通行性还取决于机器人本身的运动能力。

---

## 7. Blind Path（盲道）语义

Blind Path Mask 只能说明某些 Pixel 具有盲道语义。

不能直接推出：

\[
\boxed{
\text{整片区域都是 Safe Free Space}
}
\]

因为盲道上仍可能存在人、自行车、施工障碍、坑或台阶。

因此实际机器人更接近：

\[
Blind\ Path\ Semantic
+
Depth/Geometry
+
Obstacle
\rightarrow
Traversable\ Path
\]

---

## 8. Unknown / Uncertain（未知 / 不确定）

当区域由于：
- 强逆光
- 黑暗
- 遮挡
- 模糊
- Distribution Shift（分布漂移）

而无法可靠判断时，应允许：

\[
Unknown/Uncertain
\]

而不能直接设成：

\[
Free
\]

硬门槛：

\[
\boxed{
Unknown\neq Free
}
\]

“看不清”不等于“确认没有障碍”。

---

## 9. Mask → Depth → 3D / BEV / World

Semantic Mask 仍然在 Image Space（图像空间）。

要进入机器人空间，需要：

\[
\boxed{
Semantic\ Mask
+
Depth
}
\]

再结合相机模型得到 Camera 3D：

\[
Pixel+Depth
\rightarrow
Camera\ 3D
\]

然后通过 TF / Extrinsic（坐标变换 / 外参）：

\[
Camera
\rightarrow
base\_link
\rightarrow
map/world
\]

进一步形成 BEV（Bird's-Eye View，鸟瞰表示）或其他 World Representation（世界表示）。

完整链：

\[
\boxed{
Semantic\ Mask
\rightarrow
Depth
\rightarrow
Camera\ 3D
\rightarrow
base\_link
\rightarrow
map/world/BEV
\rightarrow
Traversability/Costmap
}
\]

---

## 10. Distribution Shift（分布漂移）

训练环境和实机环境分布不同：

\[
p_{train}(x)\neq p_{real}(x)
\]

例如白天校园训练，夜晚、雨天、地下车库部署。

这可能导致 road / grass / wall 等语义发生错误分类。

---

## 11. Temporal Consistency（时间一致性）

连续帧环境没有变化，但模型可能出现：

\[
road
\rightarrow
grass
\rightarrow
road
\rightarrow
unknown
\]

如果每帧直接写入 Costmap，可能导致：

\[
Costmap\ Flicker
\rightarrow
Planner/Controller\ Oscillation
\]

因此实际系统常需要 Temporal Fusion（时间融合）、Persistence（保持）、连续帧确认或 Timeout（超时）等机制。
