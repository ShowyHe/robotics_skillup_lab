## A. Foundation（基础）

### 1. Search Problem / State / Transition

抽象搜索问题为 `(S,A,T,s0,G,c)`：状态空间 S；动作 A；转移 T；起点 s0；目标集合 G；边代价 c。2D Grid 状态可为 `(x,y)`；Hybrid A* 由于需要考虑朝向和运动约束，常用 `(x,y,θ)`，完整机制留 Day66。**状态可达**不等于**真实机器人碰撞安全**。

### 2. Search State vs Search Node

State 是被搜索的状态；Search Node 可额外保存 `g,h,f,parent,open/closed`、队列索引等实现属性。同一 Graph State 可能由多条路径抵达。

### 3. Search Tree vs Graph Search

搜索树保存各扩展分支；Graph Search 通过状态去重、Cost 比较与 Relaxation 复用同一个状态的最好候选 `g`。有环时尤其需要状态管理。

### 4. Frontier / OPEN

Frontier（搜索前沿）是已发现、尚未正式处理的候选集合；OPEN 通常是按优先级取最小的 Priority Queue，A* 按 `f=g+h` 排序。

### 5. CLOSED / Reopen 基础

CLOSED 表示已处理/扩展的节点。对一致性 Heuristic 的标准 A*，正确出队的 Closed 节点最优 `g` 已确定；对仅可采纳但不一致的 Heuristic，实现可能必须支持更优路径触发的 Reopen。CLOSED 不是“Boolean=false，永久不可改变”的数学定理。

### 6. Goal Test / Termination

发现 Goal、Goal 进入 OPEN、Goal 正式以最小优先级弹出不是同一事件。标准最优 A* 在相应实现与 Heuristic 条件下，通常等待 Goal 被正式弹出，才可宣布最优。

### 7. Uninformed vs Informed Search

BFS 和 Dijkstra 不使用到 Goal 的剩余代价估计；A* 属于 Informed / Heuristic Search，通过 `h(n)` 启发搜索，但仍需维护实际累计 `g(n)`。

### 8. g / h / f：含义、单位、扩展规则

```text
g(n) = 已发现从 Start 到 n 的最低累计边代价
h(n) = 从 n 到 Goal 的剩余代价估计
f(n) = g(n) + h(n)
next = argmin_{n ∈ OPEN} f(n)
```

`g/h/f` 应使用相同的代价度量与单位，不能直接把以秒计算的 `g` 和以米计算的 `h` 相加。若所有 `h=0`，A* 扩展优先级退化为 Dijkstra。

### 9. 四邻接 Manhattan Heuristic

若 Grid 分辨率 `r`（m/cell），栅格坐标差为 `dx,dy`（cell），4 邻接且直行每格代价是移动距离，则：
```text
h_M = r (dx + dy)
```
障碍只能提高可行路线总代价，因此其可以成为距离下界。不能不经验证就把它用于允许更便宜斜向移动的图。

### 10. Euclidean Heuristic

```text
h_E = r sqrt(dx² + dy²)
```
表示两点直线距离；在 Edge Cost 至少包含真实几何移动距离、其余惩罚非负的条件下，直线距离是合法下界。

### 11. Octile Heuristic

对 8 邻接 Grid，直向 Cost 为 `r`、斜向 Cost 为 `sqrt(2)r`，可用：
```text
h_O = r [max(dx,dy) + (sqrt(2)-1)min(dx,dy)]
```
理由：先用 `min(dx,dy)` 步斜向同时消除横纵差，再直行剩余差。示例 dx=3、dy=4、r=1，则 `h_M=7m`、`h_E=5m`、`h_O=3sqrt(2)+1≈5.24m`。

### 12. Grid Connectivity / Corner Cutting / Resolution

4/8 邻接必须和实际 Edge Validity 一致。8 邻接时，若只检查目标斜格 Free，可能出现 Corner Cutting（穿过两个障碍夹角）。还需验证运动线段以及机器人 Footprint；Resolution 改变 Graph 粒度、几何距离与检查精度。

## B. Core Theory（核心）

### 13. Admissible Heuristic（可采纳性）

令 `h*(n)` 为从 n 到 Goal 的真实最优剩余 Cost。对所有相关节点：
```text
0 ≤ h(n) ≤ h*(n)
```
即**允许低估，不能高估**。例：`h*=12` 时，`h=7` 和 `h=12` 均可采纳，`h=15` 不可采纳。单节点满足不代表全图满足。

### 14. Consistent Heuristic（一致性）

对任意合法边 `u→v`：
```text
h(u) ≤ c(u,v) + h(v),   h(goal)=0
```
相当于 Heuristic 的三角不等式。比如 `c(A,B)=3,h(A)=9,h(B)=5`，因 `9>3+5=8`，不一致。

### 15. Consistency 为什么蕴含 Admissibility

沿着从 n 到 Goal 的最优路径反复套用一致性，所有中间 `h` 相消，得到 `h(n)≤` 该最优路径的真实 Cost，即 `h(n)≤h*(n)`；因此常见非负代价设置下 **Consistent ⇒ Admissible**，反之不一定。

### 16. Consistency 与 f 单调性的推导

如果 Relaxation 沿 `u→v`：
```text
f(v) = g(u) + c(u,v) + h(v)
     ≥ g(u) + h(u) = f(u)
```
所以沿合法路径继承的 `f` 不下降。在标准 A* 中，使用一致性 Heuristic 可避免 Closed 节点的更优 g 再次出现。

### 17. Admissibility / Reopen / Optimality 保证边界

对于维护正确 `g`、必要时允许 Reopen 的标准 Graph A*，可采纳性与非负边等条件使首次合法结束得到最优路径。只用 Admissible 但不一致的 `h`，又禁止 Closed Reopen，则一般不能保证最优。

### 18. A* 最优性直觉

假设某次弹出的 Goal 当前 `g(goal)>C*`（真实最优 Cost），则仍有最优路径上未完成的 frontier n，且正确维护的 `g*(n)+h(n)≤C*`。A* 不应先弹出更大 `f(goal)=g(goal)` 的 Goal，因此矛盾。重点：**低估不会让潜在最优路径在搜索优先级上被夸大到比次优 Goal 更贵**。

### 19. Relaxation / Parent / Stale Queue Entry

A* 与 Dijkstra 一样执行 `if g(u)+c(u,v)<g(v)` 则更新 `g(v)`、`parent(v)`、`f(v)`；可能把新的 `(v,f)` 插入堆。同一节点旧 `f` 队列项可能过期，需校验；必要时对 Closed Reopen。

### 20. 手算示例

无向非负加权图：`S-A=2,S-B=5,A-C=2,B-C=1,C-G=3,A-G=9,B-G=8`；Heuristic：`h(S)=6,h(A)=4,h(B)=4,h(C)=3,h(G)=0`。
- 弹 S：`g(A)=2,f(A)=6`；`g(B)=5,f(B)=9`，先取 A。
- 弹 A：`g(C)=4,f(C)=7`；`g(G)=11,f(G)=11`，先取 C。
- 弹 C：`g(G)=7,f(G)=7`，松弛成功，取 G。
- 最优路径：`S→A→C→G`；总代价 `7`。

### 21. Complexity / Heuristic Strength / Tie Breaking

A* 单次二叉堆操作常为 `O(log N)`，整体扩展量高度依赖搜索图和 Heuristic；最坏情况下仍需扩展大量节点，不能保证总比 Dijkstra 快。两个均可采纳的 Heuristic 若一个估计普遍更贴近 `h*`，通常更有引导性；Tie Breaking 也影响搜索序列。

## C. Advanced / Owner（进阶）

### 22. Heuristic 与实际 Cost 匹配

如果真实 Edge Cost 是距离加非负 Costmap Penalty，则 Euclidean 下界通常安全但可能偏弱。如果真实 Cost 为行驶时间，可在具有最大速度 `v_max`（m/s）的模型下考虑 `h=d_E/v_max`（秒）；必须检查速度假设与量纲。

### 23. Weighted A*（加权 A*）

```text
f_w(n)=g(n)+w h(n),   w≥1
```
`w=1` 为普通 A*；`w>1` 更强调接近 Goal 的估计，可能减少扩展、加快搜索，但失去严格最优性保证。标准条件下常能得到有界次优：`C_returned≤w C*`；这是 Cost Bound，**不是速度加速倍数，也不是安全保证**。

### 24. Anytime Search / ARA*（任意时刻修复搜索）

Anytime Search 先求初始可行解，时间允许则改善；初次找到解前不能声称“任意时刻都有路径”。ARA* 以 `f_ε=g+εh, ε>1` 开始，逐步降低 ε（如 `3→2→1`），在相应条件下缩小次优界。它复用旧搜索的 `g`、Parent、OPEN，并使用 INCONS 管理已 CLOSED 但发现更优 `g` 的节点；每轮会重新组织 OPEN/CLOSED/INCONS，而不是简单重复跑一遍 Weighted A*。复用是其重要区别。

### 25. Planning Owner Boundaries

地图 / Grid / HPA / Hybrid 搜索都需明确 State、Edge、Cost、Heuristic、Expand、Parent。A* 只优化定义的图 Cost；Graph 上的合法 Edge 不自动代表真实 Footprint 不碰撞。新 Path Cost 更低不代表应立即切换，Path Switch 仍需检查新旧路径有效性、动态障碍、时效性、Controller 可执行性及 Hysteresis/Cooldown。方案选型应同时评估路径质量、规划延迟、动态有效性和安全责任链。
