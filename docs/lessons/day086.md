## Part A — Foundation（基础层）

### 3. 标准差与方差：先分清单位

对一个控制维度：

\[
\epsilon\sim\mathcal N(0,\sigma^2)
\]

- \(\sigma\)：标准差（standard deviation）。
- \(\sigma^2\)：方差（variance）。

标准差的单位与被采样的控制量相同；方差的单位是控制量单位的平方。

差速机器人：

\[
u_t=
\begin{bmatrix}
v_{x,t}\\
\omega_{z,t}
\end{bmatrix}
\]

对应：

\[
\epsilon_t=
\begin{bmatrix}
\epsilon_{v_x,t}\\
\epsilon_{\omega_z,t}
\end{bmatrix}
\]

因此：

| 参数 | 含义 | 单位 |
|---|---|---|
| \(\sigma_{v_x}\) | 线速度扰动标准差 | m/s |
| \(\sigma_{\omega_z}\) | 角速度扰动标准差 | rad/s |
| \(\sigma_{v_x}^2\) | 线速度扰动方差 | \((m/s)^2\) |
| \(\sigma_{\omega_z}^2\) | 角速度扰动方差 | \((rad/s)^2\) |

如果把标准差和方差混淆，配置数值就会产生量纲错误。

### 4. 标准差决定搜索分布的宽度

单个控制维度：

\[
u_{k,t}=\bar u_t+\epsilon_{k,t},
\qquad
\epsilon_{k,t}\sim\mathcal N(0,\sigma^2)
\]

例如 nominal 线速度为：

\[
\bar v_x=0.4\,m/s
\]

情况 A：

\[
\sigma_{v_x}=0.05\,m/s
\]

候选线速度大多集中在 0.4 m/s 附近。

情况 B：

\[
\sigma_{v_x}=0.25\,m/s
\]

候选线速度的分布明显更宽，搜索范围更大，也更容易产生远离 nominal 的候选值。

对未裁剪的一维高斯分布：

- 约 68.3% 的样本落在均值左右 \(1\sigma\) 范围内；
- 约 95.4% 的样本落在均值左右 \(2\sigma\) 范围内。

这是概率分布性质，不代表经过速度限幅后仍保持同样的分布。

### 5. 标准差太小会怎样？

如果：

\[
\sigma_{v_x}\rightarrow0,\qquad
\sigma_{\omega_z}\rightarrow0
\]

则候选控制越来越集中在 nominal sequence 附近。

可能出现：

- 候选速度变化范围很窄；
- 很难探索明显不同的转向或加速方案；
- 当前 nominal 不合理时，候选样本可能都围绕错误的搜索中心；
- 即使 K 很大，也可能只是反复采样相似的控制序列。

注意：标准差太小不代表权重一定集中。候选代价如果很接近，归一化权重反而可能比较均匀。

### 6. 标准差太大会怎样？

如果标准差过大：

- 候选控制分布过宽；
- 很多候选可能超出底盘速度或角速度范围；
- 候选轨迹可能大量受到限幅或运动模型约束；
- 有效搜索样本可能减少；
- 代价差异可能变大，导致权重过度集中在少数样本。

这些是可能出现的结果，不是标准差变大后必然发生的现象。最终要看候选分布、约束和轨迹代价。

### 7. K 与 Standard Deviation 是两个不同维度

| 参数 | 控制什么 | 增大后的直接变化 |
|---|---|---|
| K / batch_size | 采样数量 | 候选序列更多 |
| \(\sigma_{v_x}\) | 线速度搜索范围 | 线速度扰动分布更宽 |
| \(\sigma_{\omega_z}\) | 角速度搜索范围 | 角速度扰动分布更宽 |

举例：

- K=1000，标准差很小：有大量样本，但它们集中在 nominal 附近。
- K=1000，标准差较大：样本数量不变，但候选分布更宽。
- K=2000，标准差不变：增加样本数量，不直接改变单个样本的分布宽度。

因此：

\[
\boxed{K\neq\sigma}
\]

增加采样数量不能自动解决搜索范围过窄的问题；增大标准差也不能自动弥补样本数量不足。

### 8. Control Clipping（控制限幅）

候选控制或更新后的控制序列可能受到允许范围限制。

例如：

\[
v_{\min}\leq v_x\leq v_{\max}
\]

限幅操作可以写为：

\[
v_x^{clip}=
\min\left(
v_{\max},
\max(v_{\min},v_x)
\right)
\]

假设：

\[
v_{\max}=0.5\,m/s
\]

某个候选值为：

\[
v_x=0.8\,m/s
\]

限幅后：

\[
v_x^{clip}=0.5\,m/s
\]

如果很多样本都超过上限，它们可能被裁剪到同一个边界值。

这会改变原始高斯分布：

- 原始分布可能是对称的；
- 裁剪后的分布可能不再对称；
- 边界处可能堆积大量相同数值；
- 实际有效搜索范围可能比设定的标准差更窄。

**必须区分三个位置：**

1. 原始随机扰动；
2. 加噪后的候选控制；
3. 加权更新后的 nominal control。

不同实现可能在不同阶段应用约束，不能假设所有 MPPI 都在同一位置裁剪。

## Part B — Core Theory（核心理论层）

### 9. Temperature：控制代价权重的选择性

Day85 学过：

\[
\boxed{
w_k=
\frac{\exp(-(S_k-\rho)/\lambda)}
{\sum_j\exp(-(S_j-\rho)/\lambda)}
}
\]

其中：

\[
\lambda>0
\]

temperature 不负责产生随机扰动，而是控制不同代价样本之间的权重差异。

**Temperature 较小：**

- 对代价差异更敏感；
- 低代价样本获得更大的权重；
- 权重可能集中在少数候选上。

**Temperature 较大：**

- 对代价差异不那么敏感；
- 不同候选之间的权重差异减小；
- 权重分布趋向均匀。

两个极限：

\[
\lambda\rightarrow0^+
\]

在最低代价样本唯一且数值理想的情况下，权重趋向集中在该样本。

\[
\lambda\rightarrow\infty
\]

权重趋向均匀：

\[
w_k\rightarrow\frac1K
\]

### 10. 数值比较：小 Temperature 与大 Temperature

三条候选轨迹的代价：

\[
S=[0,1,2]
\]

先减去最小代价：

\[
\rho=0
\]

**情况 A：**

\[
\lambda=0.5
\]

归一化权重约为：

\[
w=[0.867,\ 0.117,\ 0.016]
\]

最低代价样本占据主要权重。

**情况 B：**

\[
\lambda=2
\]

归一化权重约为：

\[
w=[0.506,\ 0.307,\ 0.186]
\]

另外两条候选轨迹的贡献明显增加。

结论：

\[
\boxed{
\lambda\downarrow
\Rightarrow
\text{权重分布更尖锐}
}
\]

\[
\boxed{
\lambda\uparrow
\Rightarrow
\text{权重分布更平坦}
}
\]

temperature 不改变候选控制原本的采样标准差，也不直接扩大或缩小搜索范围。

### 11. Effective Sample Size（有效样本量）

虽然本轮有 K 条候选轨迹，但如果权重高度集中在一两条轨迹上，真正对更新有明显贡献的样本就比较少。

可以用有效样本量（ESS）描述权重集中程度：

\[
\boxed{
N_{\mathrm{eff}}=
\frac{1}{\sum_{k=1}^{K}w_k^2}
}
\]

范围：

\[
\boxed{1\leq N_{\mathrm{eff}}\leq K}
\]

两个边界：

**所有权重相等：**

\[
w_k=\frac1K
\]

则：

\[
N_{\mathrm{eff}}=K
\]

**只有一条样本权重为 1：**

\[
w=[1,0,\ldots,0]
\]

则：

\[
N_{\mathrm{eff}}=1
\]

ESS 是从归一化权重计算出来的诊断指标，不等于实际采样数量，也不代表这些样本一定安全或质量高。

### 12. 用 ESS 观察 Temperature 的效果

沿用上一题：

\[
S=[0,1,2]
\]

当：

\[
\lambda=0.5
\]

权重：

\[
w=[0.867,0.117,0.016]
\]

得到：

\[
N_{\mathrm{eff}}\approx1.31
\]

当：

\[
\lambda=2
\]

权重：

\[
w=[0.506,0.307,0.186]
\]

得到：

\[
N_{\mathrm{eff}}\approx2.59
\]

说明在这组代价下，提高 temperature 让更多样本对更新产生明显贡献。

但不能单独凭 ESS 判断控制质量：

- ESS 低：可能是 temperature 太低，也可能是候选代价差异确实很大；
- ESS 高：可能是 temperature 太高，也可能是所有候选代价都很接近；
- ESS 高不代表采到了好的轨迹；
- ESS 低也不必然意味着算法错误。

必须结合候选轨迹、Cost 和权重一起分析。

### 13. Sigma、Temperature、K 的职责不能混淆

| 参数 | 所在环节 | 核心作用 |
|---|---|---|
| K | Sampling | 采样多少条候选序列 |
| \(\sigma\) | Sampling | 候选控制分布有多宽 |
| \(\lambda\) | Weight | 代价差异对权重影响有多强 |

它们分别回答：

- K：采多少条？
- Sigma：往多大范围搜索？
- Temperature：更偏向低代价样本，还是让更多样本共同参与？

这三个参数不能相互替代。

### 14. Warm Start：为什么复用上一周期的控制序列？

Day85 已经学习了 Shift：

\[
\bar U_{k+1}^{init}
=
[
\bar u_1^{new},
\ldots,
\bar u_{N-1}^{new},
\bar u_{\mathrm{tail}}
]
\]

这就是常见的 warm start（热启动）方式。

含义：

1. 上一周期已经优化出一条未来控制序列；
2. 当前周期已经执行了靠前的一步；
3. 原来的第二步成为当前时刻附近的初始猜测；
4. 将剩余序列向前移动；
5. 再围绕新的 nominal sequence 采样和优化。

好处：

- 不需要每个周期都从完全陌生的序列开始；
- 相邻周期的控制搜索中心通常更连续；
- 有助于保持控制输出的时间连续性；
- 可以利用上一周期已经计算出的优化结果。

但 warm start 只是初始猜测，不代表旧序列已经适应当前环境。

### 15. Temporal Consistency：Shift 必须与时间对齐

假设：

\[
\Delta t_{\mathrm{model}}=0.05s
\]

控制器每隔：

\[
T_c=0.05s
\]

更新一次。

那么每个控制周期过去后，预测时间窗口正好前移一个模型步长，可以将序列 shift 一格。

但如果：

\[
T_c\neq\Delta t_{\mathrm{model}}
\]

就不能不加判断地认为每个控制周期都应该简单移动一个索引。

因为：

- 控制器时间窗口移动了多少；
- 模型预测序列每个索引代表多少时间；

两者必须匹配。

否则可能出现控制序列与真实时间错位。

对于时间间隔发生变化的实现，可能需要重新对齐、重采样或重置序列，具体取决于控制器实现。

### 16. Stale Warm Start：什么时候旧序列会失效？

以下变化可能使上一周期的控制序列不再适合作为当前搜索中心：

- 前方突然出现障碍物；
- 全局路径发生明显切换；
- 定位发生跳变；
- 实际速度与预测速度出现明显偏差；
- 机器人长时间暂停；
- 急停触发；
- 控制模式发生切换。

举例：

上一周期 nominal sequence 是持续直行：

\[
\bar v_x=0.5\,m/s
\]

执行过程中前方突然出现障碍。

如果仍然机械地使用旧序列作为搜索中心，而新的候选采样又不足以覆盖有效绕行方案，控制器可能需要多个周期才能明显改变搜索方向。

因此：

\[
\boxed{
Warm\ Start\neq Blind\ Reuse
}
\]

正确做法是：

**复用旧序列作为初始猜测，但必须基于当前状态和当前环境重新 rollout、评价和更新。**

### 17. 三种数据必须严格区分

这是本日最重要的工程知识点之一。

| 数据 | 含义 | 是否代表真实运动 |
|---|---|---|
| Old Command | 上一周期发送的速度命令 | 否 |
| Nominal Sequence | MPPI 内部保存的未来控制序列 | 否 |
| Actual State / Feedback | 当前机器人状态估计与实际速度反馈 | 用于描述真实运动，但仍有估计误差 |

数学上：

\[
u_{\mathrm{cmd}}^{old}
\neq
\bar U
\neq
\hat x_{\mathrm{actual}}
\]

它们的作用不同：

- Old Command：过去希望机器人执行什么。
- Nominal Sequence：当前准备围绕什么控制序列进行搜索。
- Actual State：机器人现在实际处于什么状态。

不能用旧 command 代替当前实际速度。

### 18. MPPI 的初始 Rollout State 从哪里来？

每轮预测需要一个明确的初始状态：

\[
\boxed{x_{0|k}=\hat x_k}
\]

这里的 \(\hat x_k\) 应来自当前有效的状态估计或反馈输入。

对于移动机器人，可能涉及：

- 当前位姿；
- 当前线速度；
- 当前角速度；
- 必要时的其他动力学状态。

具体包含哪些状态取决于运动模型。

例如：

如果模型包含速度状态，那么必须正确初始化当前实际速度，不能把过去的速度命令直接当成实际速度。

如果模型采用理想速度输入的简化运动学模型，则要明确速度命令与实际速度之间的模型假设，不能默认执行器瞬时响应。

**关键不是每种模型都必须使用相同的状态向量，而是初始状态的数据来源必须明确且足够新鲜。**

### 20. Nav2 Humble：Noise Generator

源码：

[noise_generator.cpp](https://github.com/ros-navigation/navigation2/blob/humble/nav2_mppi_controller/src/noise_generator.cpp)

主要行为：

1. 根据 batch_size 和 time_steps 生成扰动数组；
2. 线速度和角速度分别使用对应标准差生成高斯随机数；
3. 将扰动加到 control sequence 上；
4. 得到带噪的候选控制。

核心逻辑：

\[
u_{k,t}=\bar u_t+\epsilon_{k,t}
\]

源码中：

- vx 使用 vx_std；
- wz 使用 wz_std；
- 每个候选样本、每个预测步都有对应的噪声值。

注意：Noise Generator 本身没有在这段生成函数中单独插入一条零噪声样本。因此不能不看实现就认定每个 MPPI 都会把 nominal sequence 原样作为一个候选样本进行评价。

### 21. Nav2 Humble：Optimizer 的状态输入

源码：

[optimizer.cpp](https://github.com/ros-navigation/navigation2/blob/humble/nav2_mppi_controller/src/optimizer.cpp)

在 Optimizer::prepare() 中，传入的：

- robot_pose；
- robot_speed；

被保存到本轮状态中。

这说明状态输入与 nominal control sequence 是不同的数据来源。

每轮流程大致为：

\[
\text{Robot Pose / Speed}
\rightarrow prepare()
\rightarrow optimize()
\rightarrow Output
\rightarrow Shift
\]

这也是为什么旧 command 不能代替当前机器人速度反馈。

### 22. Nav2 Humble：Temperature 与权重更新

在 Optimizer::updateControlSequence() 中：

1. 对候选 cost 进行最小值归一化处理；
2. 根据 temperature 计算指数权重；
3. 归一化权重；
4. 对候选控制序列进行加权求和；
5. 应用控制序列约束。

其权重核心形式：

\[
w_k\propto
\exp\left(
-\frac{S_k-\rho}{temperature}
\right)
\]

但 Nav2 Humble 还包含与 gamma、采样标准差及控制扰动相关的代价修正项。

所以不能把 Day85 的基础公式当成源码中的全部计算。

### 23. Nav2 Humble：Shift 与时间对齐

源码：

[optimizer.cpp — setOffset / shiftControlSequence](https://github.com/ros-navigation/navigation2/blob/humble/nav2_mppi_controller/src/optimizer.cpp)

Humble 分支中：

- 控制周期与 model_dt 相等时，开启控制序列 shift；
- 控制周期小于 model_dt 时，代码发出警告；
- 控制周期大于 model_dt 时，代码抛出异常。

启用 shift 时，序列向前滚动一格，并将末尾位置补为原来的末尾控制值。

这说明 shift 不是随便移动数组索引，而是与控制周期和预测时间网格有关。

具体行为以该版本源码为准，不能直接推广到所有 MPPI 实现。

### 24. Nav2 Humble：Control Clipping

源码：

[optimizer.cpp — applyControlSequenceConstraints](https://github.com/ros-navigation/navigation2/blob/humble/nav2_mppi_controller/src/optimizer.cpp)

该函数会对控制序列执行：

\[
v_{\min}\leq v_x\leq v_{\max}
\]

\[
-\omega_{\max}\leq\omega_z\leq\omega_{\max}
\]

再调用运动模型应用相应约束。

在这份实现中，更新后的控制序列会经过约束处理。

这意味着你需要区分：

- 原始 noise；
- 候选控制；
- 加权更新结果；
- 约束处理后的最终控制序列。

如果只记录最后的 cmd_vel，就无法判断速度是原本没有采样到，还是在后续约束环节被裁剪。

### 25. 急停恢复：Old Command 不能代替 Actual Velocity

结合你的机器狗底盘情况：

你此前确认：

- 按住急停时，底盘进入 DISABLED；
- 电机失能，轮子自由转；
- 软件发零速不能实现主动制动；
- 松开急停且速度为零时，底盘可以进入 LOCKED 状态。

因此急停恢复尤其需要区分：

\[
u_{\mathrm{old}}
\]

\[
\bar U_{\mathrm{old}}
\]

\[
\hat x_{\mathrm{actual}}
\]

假设急停前：

\[
u_{\mathrm{old}}=
\begin{bmatrix}
0.5\\
0.2
\end{bmatrix}
\]

急停期间，机器人可能被人推动，也可能因为惯性继续移动。

此时不能因为旧 command 是 0.5 m/s，就认定机器人当前速度仍然是 0.5 m/s。

也不能因为急停触发，就默认实际速度已经变成零。

**正确的恢复流程：**

1. 急停期间，确保安全状态优先级高于 MPPI 输出。
2. 松开急停后，检查底盘当前工作状态。
3. 获取新鲜的轮速、里程计和必要的 IMU 反馈。
4. 确认实际速度，而不是沿用旧 command。
5. 如果确认机器人已经静止，可以按照实现规则重置或初始化 nominal sequence。
6. 如果机器人仍在移动，不能直接假设零速；必须基于当前状态及可用的安全控制机制处理。
7. 获取当前位姿、速度与最新路径后，再恢复正常优化。

如果反馈时间戳过期，或者当前速度无法可靠确定，就不能把状态当成已经确认。

### 26. Warm Start 的工程风险与诊断证据

当机器人出现急停恢复后突然转向、速度突变或旧动作重放，需要重点核对：

| 证据 | 检查目的 |
|---|---|
| old command | 上一次发送了什么命令 |
| nominal sequence before shift | 内部旧控制序列是什么 |
| nominal sequence after shift | shift 是否正确 |
| actual vx / wz | 当前真实速度反馈 |
| pose / speed timestamp | 状态是否新鲜 |
| plan identity / path | 是否发生路径切换 |
| model_dt / controller period | 时间网格是否一致 |
| vx_std / wz_std | 搜索分布是否合理 |
| temperature | 权重是否过度集中 |
| clipping ratio | 有多少控制值被限幅 |
| ESS | 权重分布是否过度集中 |

不能只看最终速度命令。

需要确定究竟是：

- 旧 nominal sequence 没有清理；
- shift 时间对齐错误；
- 新状态反馈没有正确进入优化器；
- 噪声搜索范围不合理；
- temperature 造成权重过度集中；
- 控制限幅导致更新结果发生变化。

### 27. 推荐调参顺序

不要同时调整 K、sigma、temperature 和控制限幅。

建议按以下顺序：

**第一步：核对基础条件**

- 运动模型；
- 控制单位；
- 最大线速度、最大角速度；
- 速度反馈；
- model_dt 和控制周期。

**第二步：调整 Sampling Standard Deviation**

先观察候选速度分布是否覆盖了有意义的搜索范围。

不要让大量候选控制无意义地超出底盘能力。

**第三步：调整 Temperature**

在采样范围合理后，再观察权重是否过度集中或过于平均。

**第四步：观察 ESS**

结合候选 Cost、权重和轨迹质量判断是否需要调整。

**第五步：调整 K**

在计算预算允许的情况下增加候选样本数量，观察搜索覆盖与控制周期耗时。

一次尽量只改变一个参数组，使用相同场景进行对比。
