## 1. Train / Validation / Test

Train Set（训练集）：用于训练并更新 Parameter（参数）。

Validation Set（验证集）：用于选择模型、调整 Hyperparameter（超参数）、观察是否 Overfitting（过拟合），通常不直接更新 Parameter。

Test Set（测试集）：训练和调参结束后，用于最终评价未见数据上的泛化能力。

\[
\boxed{\text{Validation 用于开发选择，Test 用于最终评价}}
\]

## 2. Generalization（泛化）

Generalization 指模型在没见过的新数据上仍然保持较好性能。

机器人真正需要的是对真实部署环境的泛化，而不是只让 Train Loss 很低。

## 3. Overfitting / Underfitting

Overfitting（过拟合）典型表现：

\[
Train\ Loss\downarrow,\qquad Validation\ Loss\uparrow
\]

Underfitting（欠拟合）典型表现：

\[
Train\ Loss\text{高},\qquad Validation\ Loss\text{也高}
\]

## 4. Overfitting 不等于 Distribution Shift

Overfitting：模型过度适应 Training Set 的细节。

Distribution Shift（分布漂移）：

\[
p_{train}(x)\neq p_{real}(x)
\]

例如白天校园训练、夜晚城市道路部署，首先应判断为 Distribution Shift。

二者可以同时存在，但不是同一个概念。

## 5. Data Leakage（数据泄漏）

如果 Train / Test 使用同一条视频中的相邻连续帧，测试数据可能与训练数据高度相似，导致虚高的 Test Performance（测试性能）。

机器人数据常需要按场景、路线、时间、设备等粒度拆分。

## 6. Input Normalization（输入归一化）

例如：

\[
0\sim255\rightarrow0\sim1
\]

或者：

\[
x'=\frac{x-\mu}{\sigma}
\]

目的不是“让数字越小越好”，而是让输入数值尺度更稳定，使优化更容易。

## 7. Batch Normalization（批归一化）

Batch Normalization 处理网络内部 Activation / Feature（激活值 / 特征），不是 Parameter。

Training 时依赖当前 Batch 的统计量；Inference 时通常使用训练期间积累的统计量。

\[
\boxed{\text{BatchNorm 依赖 Batch 统计}}
\]

## 8. Layer Normalization（层归一化）

Layer Normalization 主要对单个 Sample / Token 自己的 Feature 维度做归一化，不依赖其他 Sample 的 Batch 统计。

\[
BN\rightarrow依赖Batch统计
\]

\[
LN\rightarrow不依赖其他Sample的Batch统计
\]

## 9. Regularization（正则化）

常见方法：
- Weight Decay（权重衰减）
- Dropout（随机失活）
- Data Augmentation（数据增强）

目标是减少模型对训练数据特殊细节的过度依赖。

## 10. Weight Decay（权重衰减）

\[
J_{total}=J_{data}+\lambda\|W\|^2
\]

不是要求 Weight 越小越好，而是在拟合数据与限制复杂度之间做权衡。

## 11. Dropout（随机失活）

Training：开启 Dropout，随机关闭部分神经元，减少固定依赖。

Inference / Evaluation：关闭 Dropout，使模型稳定地使用完整网络进行预测。

## 12. Data Augmentation（数据增强）

核心要求是输入变化后，Task Label（任务标签）的语义仍保持正确。

Robot Policy 图像左右镜像时：

\[
(v,\omega)\rightarrow(v,-\omega)
\]

因为左右转向方向反转。

## 13. Distribution Shift 对机器人更严重

机器人形成：

\[
Perception\rightarrow Decision\rightarrow Action\rightarrow Environment
\]

Lighting（光照）、Camera Pose（相机位姿）、Weather（天气）、Ground（地面）、Sensor Noise（传感器噪声）等变化都可能把感知误差继续传播到规划和控制。

## 14. Model Metric 不等于 Robot Task Success

例如 mAP 从 0.70 提升到 0.80，但近距离行人漏检增加，不能仅凭 mAP 上升就判断新模型更适合机器人导航。

还需要看 Collision Rate（碰撞率）、Success Rate（成功率）、Emergency Stop Rate（急停率）、Path Completion Rate（路径完成率）等任务级指标。
