## 1. 今日目标与知识链

理解大型地图为何先抽象成高层图、局部边故障怎样处理，以及搜索结果如何在地图更新时复用，而不是每次从头搜索。

**主线：原地图 → 区域/入口 → 抽象图 → 起终点接入 → 高层路线 → 细化验证 → 边状态更新/增量修复。**

## A. Foundation（01–08）

### 01. Hierarchy / Abstraction（层级与抽象）

在大型网格上直接 A* 可能扩展大量栅格。HPA*（Hierarchical Path-Finding A*）把局部区域归成 Cluster/Region（簇/区域），通过入口点 Portal/Gateway（门口/连接口）构造更小的 Abstract Graph（抽象图）。**抽象减少搜索规模，但可能引入路径次优与建模误差。**

### 02. Node / Edge / Cost

- Node：抽象状态、地标或入口。
- Edge：节点间允许的转移关系，带有方向、可行性、代价。
- \(\,G=(V,E)\,\)；路径 \(P=(v_0,\dots,v_k)\)，累计代价 \(C(P)=\sum c(v_i,v_{i+1})\)。
- **物理阻塞的是哪条通行关系，要先证明；不应默认整个 Node 都失效。**

### 03. Portal 与 Cluster 内部连接

相邻 Cluster 有通行开口时可以设置 Portal；同一个 Cluster 内部的 Portal 之间可以通过低层搜索计算路径和代价。高层边只有在对应低层通路已定义且当前仍有效时，才有可用性含义。

### 04. Precomputation 与 Graph Reuse

静态拓扑可以离线/启动时预计算区域内距离、入口连接；在线规划复用这些结果。地图或机器人可行性约束改变后，应考虑缓存过期与增量更新，不得无限期假设原始低层通路一直畅通。

### 05. Start/Goal Attach（把实时起终点接入高层图）

当前机器人位置和目标点未必正好是图节点，需搜索合法接入边。可能的方法包括：
- K-nearest 候选节点 + 实际可通行验证；
- LOS（视线）+ Footprint/障碍碰撞检查；
- JPS/A* 等低层图搜索连接。

**最近的地标不必然可到达；不能仅凭欧氏距离建立可执行接入边。**

### 06. High-level Search 与 Local Refinement

在抽象图上求出 Portal/Node 序列，仅代表高层候选路线。还必须将抽象边映射到低层路径并复验；若细化失败，更新相应边/代价后再尝试搜索。高层路通不等于机器人实际运动无碰撞。

### 07. Abstraction Error

抽象会损失信息：细窄通道可能被合并、边代价近似、动态障碍可能尚未反映到预计算结果。应明确抽象图的分辨率、允许误差与验证责任，不把抽象最短路直接当作真实最短路。

### 08. 动态边状态

最简模型是

\[
c_t(e)=
\begin{cases}
c_{\mathrm{normal}}(e),&\text{已验证可用}\\
+\infty,&\text{确认当前不可通行}
\end{cases}
\]

更完整实现可有 Unknown / Suspected / Temporarily Blocked 等状态，但这些是**设计选项**，并非所有 HPA 实现都已存在。

## B. Core Theory（09–16）

### 09. Edge Failure vs Node Failure

若 \(575\rightarrow576\) 的通道被阻挡，只能确定该方向/路径不可用时，优先失效的是**这条边**；删除整个 576 可能无端删除它通往其他节点的合法边。若证据表明节点区域全部不可进入，才考虑节点整体不可用。双向是否同时封闭依赖通行模型与证据。

### 10. TTL、故障记忆与恢复

临时阻塞可登记：edge ID、失败原因、时间戳、置信/计数、有效期 TTL、上次验证数据。TTL 到期**不意味着通道自动安全**：应按设计进入待验证、再采样或重试状态，确认有效后再恢复；若是永久地形变化则应持久更新地图/图结构。

### 11. 禁止无条件直线 Fallback

当高层路径找不到或 Attach 失败时，不能直接把欧氏最短直线当作安全路径。任何替代方案（LOS、A*、JPS、直接导航）都必须满足对应碰撞、Footprint、运动可行性检查。验证失败就不能宣称该 Fallback 有效。

### 12. Incremental Search（增量搜索）的动机

通常 A* 对每次问题重新计算；增量搜索保留上次搜索状态，当部分 Edge Cost 改变时优先修复受影响的状态。它可能节约搜索，但效果取决于变化范围与算法结构；**不是只检查障碍处、不再考虑终点连通性。**

### 13. LPA* 的 \(g\) 与 \(rhs\)

- \(g(s)\)：状态 \(s\) 当前保存的路径代价估计。
- \(rhs(s)\)：根据其前驱的 \(g\) 与边代价得到的“一步前瞻”代价。

对一般非起点状态：

\[
rhs(s)=\min_{s'\in Pred(s)}\big(g(s')+c(s',s)\big).
\]

按常见 LPA* 初始化，\(rhs(start)=0\)。若 \(g(s)=rhs(s)\) 为局部一致；不相等就是不一致，需要在修复过程中处理。**仅仅发现一处边代价变化，不能断言最终只更新一个节点。**

### 14. LPA* 怎么复用旧搜索

一次搜索完成后保存 \(g,rhs\)、优先队列及图；边代价变化时更新其影响到的节点（及依赖关系），将不一致状态纳入队列，再按优先级传播修复，直到相关终点条件恢复一致性。若变动大，收益可能不及重启搜索。

### 15. D* Lite 与 LPA* 的联系和区别

D* Lite 借鉴 LPA* 的 \(g/rhs\) 与局部一致性维护，但**通常从固定目标向会移动的机器人起点进行反向成本传播**，并调整优先级键以复用上一轮搜索。它不等于“只更新机器人当前点”；实际受影响状态可以沿图传播。

### 16. 一个最小路径修复例子

已有抽象路线 \(A\rightarrow B\rightarrow D\)，总代价 \(2+2=4\)；另有 \(A\rightarrow C\rightarrow D\)，代价 \(3+3=6\)。若 \(B\rightarrow D\) 被可靠判定阻塞并设为 \(+\infty\)，重新计算可得到经过 \(C\) 的路线，代价 6。

- 从头 A*：在更新后的图上完整重新搜索。
- 增量方法：尽量复用以前保存的代价状态，对这次修改的相关节点修复。
- 不论方法，**执行时仍需低层细化和碰撞验证**。

## C. Advanced / Owner（17–22）

### 17. HPA 与增量搜索是两个维度

HPA 回答“**在哪张分层图上搜索**”；增量搜索回答“**图变了如何复用以前的计算**”。它们可以结合，也可以独立使用。一个采用 HPA 的系统不一定实现了 LPA* 或 D* Lite。

### 18. 动态障碍对 HPA 的影响链

~~~text
Obstacle / Costmap update
          ↓
Edge / local corridor validity check
          ↓
Invalidation / TTL / confidence update
          ↓
High-level path search or incremental repair
          ↓
Local refinement + collision validation
          ↓
Accept path or report no verified route
~~~

若是行人临时挡住门口，先判断该问题属于临时边阻塞、感知误报、局部控制等待，还是拓扑通行能力确实改变。

### 19. 真实机器人系统的证据链

排查应区分：地图时间戳、世界障碍帧、Footprint、安全边界、Attach 候选、Edge ID/方向/代价、搜索候选路径、低层碰撞失败位置、控制层停车原因。不要把“world_stop”四个字符自动推断成 HPA 某条边必然失效。

### 20. Path Switching 前置关系

高层重新得到一条可行路径，还不代表必须立刻切换；保留旧路、切换新路、等待或 Recovery 由任务策略决定，Day69 专门学习 Persistence、Hysteresis、Cooldown、Switch Benefit。Day68 重点是图、有效性与修复。

### 21. 性能 Trade-off

预热缓存减少在线搜索但增加内存与一致性维护；Cluster 大小、Portal 密度影响高层图大小与抽象误差；频繁封边可能导致路线震荡；长 TTL 可能错失通道恢复。需要日志/离线回放对比而不是凭直觉断定最佳参数。

### 22. 教学迁移题（新增练习，不属于历史考试）

- 门口某条边失效，附近节点还有其他出口：应该删除节点还是更新边？
- TTL 到期后，能否直接将该边重新标成安全可通行？
- 机器人起点移动且前方边代价变化：D* Lite 与每次从头 A* 复用信息的区别是什么？

**参考判断：** 一般优先更新被证实失效的边；TTL 到期仍须考虑重新验证；D* Lite 通过保存和修复代价状态复用已有搜索结果。

## Key Knowledge

1. HPA (Hierarchical Pathfinding A*) reduces search scale by clustering grid maps into abstract regions.

2. Cluster contains representative nodes / entrances. Connections between clusters are represented as edges.

3. Node represents a state or landmark. Edge represents transition feasibility and cost.

4. A failed route such as 575→576 is usually an Edge Failure, not a Node Failure.

5. Deleting a node removes unrelated connections. Updating edge cost preserves graph structure.

6. Dynamic edge update:

normal: cost = finite
blocked: cost = infinity

7. Incremental Search reuses previous search information instead of restarting full A* after every map change.

8. LPA* maintains g and rhs values. When g != rhs, the node requires update.

9. D* Lite applies incremental repair ideas to robot navigation with changing environments.

10. Failure memory should record:
- edge
- failure reason
- timestamp
- failure count

11. Temporary blockage should not become permanent deletion because dynamic obstacles may disappear.

For robot navigation:

HPA provides large-scale topology.
Local planner executes motion.
Failure detection updates graph cost.
Planner repairs affected regions.
