## 1. 今日目标与核心链路

将动态障碍、全局规划、路径质量、时序轨迹和控制反馈串成一条可排查的工程证据链。

~~~text
World / Pose / Costmap（含时间与不确定性）
                    ↓
          Feasibility + Global Planner
                    ↓
            Geometric Path（几何路径）
                    ↓
     [可选] Smoothing + 重新碰撞检查
                    ↓
        Local Controller / Trajectory optimization
                    ↓
            cmd_vel → Robot
                    ↓
               Feedback
~~~

图仅代表常见责任划分。具体模块边界依实现而变，MPPI 常作为**Controller 内部轨迹采样/优化方法**，不必存在独立于 Controller 的“轨迹优化服务器”。

## A. Foundation（01–09）

### 01. Path 与 Trajectory 根本不同

Path 描述几何/构型序列，例如二维 \(\{(x_i,y_i,\theta_i)\}\)；不必携带每一点的执行时间。Trajectory 至少定义随时间的状态或位姿 \(q(t)\)，通常还可导出/指定 \(\dot q(t)\)、\(\ddot q(t)\)。**“Execution State”不是轨迹数学定义的必要组成。**

### 02. 路径参数与时间参数

Path 可以按弧长 \(s\) 表示为 \(p(s)\)；Trajectory 把弧长与时间建立联系 \(s=s(t)\)：

\[
p(t)=p(s(t)),\qquad
\dot p(t)=\frac{dp}{ds}\dot s(t).
\]

因此，一条相同几何路径可以对应不同速度曲线、不同所需时间与不同动态可行性。

### 03. 基本速度与加速度

\[
v(t)=\frac{ds}{dt},\qquad
a(t)=\frac{dv}{dt}
\]

这里 \(s\) 为沿路径的弧长。在曲线路径上还有法向加速度需求；只验证没有碰撞、不限制速度和加速度，不能推导出底盘能执行。

### 04. Clearance（安全净空）

Clearance 可以定义为路径上的机器人几何体到障碍的最小距离（具体度量必须声明）。中心线离墙 0.2m 不等于具有 0.2m 的车身余量；真实 Footprint、朝向和膨胀/安全边界必须参与计算。

### 05. Curvature（曲率）与 Heading Change

以弧长参数化、满足相关光滑性时，曲率可写成：

\[
\kappa(s)=\frac{d\theta}{ds},\qquad R(s)=\frac{1}{|\kappa(s)|}\quad(\kappa\ne0).
\]

急剧航向变化会提高转向与角速度需求；路径存在几何可行性，不保证车辆/底盘在给定 \(v,\omega,a\) 约束下按期完成。

### 06. Narrowness / Reverse / Costmap Cost

窄路、高膨胀代价、倒车、频繁转向，可能影响整体执行风险、舒适度、控制器跟踪精度与任务耗时。对于特定机器人，倒车是否允许、代价如何权衡由运动模型、碰撞检查和规划代价决定，不能统一断言“所有情况都要禁止倒车”。

### 07. Smoothing（平滑）不替代规划

Smoother 处理已有路径的曲率/连续性等质量，不保证始终保留原路径的碰撞合法性。平滑后的路径**必须重新验证 Footprint、障碍和运动约束**；并非所有 Planner 输出都必须进入平滑器。

### 08. Global 与 Local 的响应时间尺度

Global Planner 解决较大范围路线选择；Local Controller 响应当前运动与近场约束；BT/任务策略协调等待、重新规划和切换。**“短期动态障碍=一定由局部解决”不是普适规定**，应按持续性、观测时效、可绕空间和系统安全策略判断。

### 09. Dynamic Obstacle 的时间属性

障碍测量不仅包含位置，还应考虑观测时戳、有效期、运动速度/预测（如果可用）。行人刚好离开的位置不能沿用旧“blocked”无限久；单帧短暂消失也不能自动视为安全通过。观测与确认时间必须可比较。

## B. Core Theory（10–17）

### 10. Trajectory Optimization 基本数学形式

典型离散优化问题可写为：

\[
\min_{\{x_k,u_k\}}\ \sum_{k=0}^{N-1}\ell(x_k,u_k)+\ell_f(x_N)
\]

满足：

\[
x_{k+1}=f(x_k,u_k),\quad x_0=\hat x_0,\quad
x_k\in\mathcal X_{\mathrm{safe}},\quad u_k\in\mathcal U.
\]

\(\ell\) 可组合路径偏差、障碍风险、速度/控制平滑、终点误差；优化还可包含边界与动力学约束。**这是概念模型，不代表当前某个 MPPI 插件的真实代价函数。**

### 11. 参考路径与优化轨迹的关系

Global Path 常作为局部控制器的几何 Reference。局部轨迹优化会在有限预测时域里根据状态、障碍、模型与约束选择运动；优化可能离开参考中心线以避障，但若全局路径根本不可到达，局部优化通常不能替代大范围拓扑重规划。

### 12. 轨迹时间参数化的最小例子

二维一米直线段，从静止起步、恒加速度 \(a=0.5\,\mathrm{m/s^2}\)，假设不受速度上限且不考虑末端停车：

\[
s(t)=\tfrac12at^2=0.25t^2,\qquad
v(t)=at=0.5t.
\]

到达 \(s=1\,\mathrm m\) 时 \(t=2\,\mathrm s\)，末速 \(1\,\mathrm{m/s}\)。若末端必须静止或速度上限更低，需换一条满足边界条件的速度曲线。**路径长度相同，执行时间也可能不同。**

### 13. Dynamic Cost 与 Freshness

对于同一栅格，是否为静态墙、可靠临时障碍、旧观测残留或未知区域，决定不同的处理策略。使用障碍点时应检查 sensor frame、时间戳、TF 可用性、更新/清除策略、空间覆盖和数据融合延迟，而不只是读取某一刻的代价值。

### 14. Path Quality：不只是最短距离

可考虑的指标：Path Length、最小 Clearance、最大 Curvature/角度突变、Reverse 次数、与当前位置连接代价、时间可行性、控制努力、切换成本。在比较多目标代价时，先说明单位和归一化方式，不能把不同量纲直接加总后称为“最优”。

### 15. Global Replan 与 Path Switch

重新规划得到候选路径属于 Planner 层；是否采用新路需要考虑旧路径仍否安全、候选路径是否可靠、持久化/滞回/冷却、当前底盘运动状态。频繁 Replan 不必然导致 Switch，频繁 Switch 也不必然是 Planner 算法本身错误。

### 16. Planning Under Uncertainty 的最小边界

若定位估计有误差、障碍点测量不确定或观测过期，则“当前点到障碍的估计距离”不是确定的真实净空。可用更保守的安全边界、时效检验、与不确定性关联的碰撞风险判断。**不能将协方差当 0**；也不能只因为使用了概率方法就宣称具备安全保证。

### 17. 一条无碰撞 Path 为什么可能无法执行

例：几何路径通过一条窄路且没有碰撞，但在入口需要瞬时从 \(v=0.5\) 变为 \(v=0\) 或产生超出角速度限制的急转弯。即便位置序列可行，速度/加速度/执行器约束仍可能不可行；应区分路径几何合法、运动学可行和动态/控制可行。

## C. Advanced / Owner（18–24）

### 18. Failure Taxonomy（按现象分层，不作唯一归因）

- 无有效 Global Path：地图/Footprint/目标/Planner/搜索预算等；
- Path 几何绕大弯或贴墙：代价、搜索权重、障碍、后处理或路径切换等；
- Path 合理但命令慢：Controller 优化/约束、速度反馈、局部障碍等；
- cmd_vel 正常但底盘不跟：通信、底盘跟速模型、执行器和安全门控；
- 原路与新路反复切：重规划触发、Path Switch 策略、路径评估时效/可行性；
- 障碍早已消失但仍绕行：Costmap 数据时效、清除/跟踪、图/边缓存。

**以上只是排查假设，需日志和数据逐项验证，不可直接认定根因。**

### 19. 证据链应如何采集

~~~text
Goal / task ID / BT阶段与时间戳
 → localization pose + covariance / TF
 → 原始感知与world/costmap帧
 → Footprint/Collision判定
 → Planner输入、候选与最终Path
 → Smoother前后Path
 → Controller输入Path、状态、候选trajectory、cmd_vel
 → 实际里程计/底盘反馈
 → Replan/Switch/Recovery事件
~~~

应尽量保证统一时基、同一 Map/Frame、同一 Path ID。若只拿到每次导航开始的稀疏 Pose，无法据此重构完整运动轨迹。

### 20. 真实场景：提前绕与钻窄路

先提取同一时间切片的 Footprint、膨胀代价、路径、机器人实际位姿/轨迹、Controller 命令；再判断是 Planner 选路、Costmap 清除滞后、局部控制追踪、PathSwitchGuard 或底盘跟踪造成。**不能只凭“走得不好”确认某个模块有 bug。**

### 21. 真实场景：绕行之后突然回拉

分别核对全局路的重新发布时刻、目标相同与否、旧路是否仍被执行、Path Switch 决策、局部 trajectory 的跟踪误差。新 Path 的 Geometry、BT 切换策略和 Controller 轨迹都可能引发类似表象。

### 22. 工程边界：HPA / Hybrid A* / Smoother / MPPI

一种常见系统分工：

~~~text
HPA (abstract route) → Hybrid A* / Global Planner
                     → Global Path
                     → optional Smoother + collision recheck
                     → MPPI Controller (trajectory candidates, cmd_vel)
                     → Robot
~~~

仅作为**可能的系统架构示意**，不代表这几个软件一定串接、也不证明公司代码采用了这些具体接口。

### 23. Planning Owner 的判断原则

判断一条轨迹是否可用，需要把静态/动态障碍、数据新鲜度、可通行状态、速度/加速度限制、路径切换成本和真实控制反馈共同考虑。设计上的安全约束和现场是否真正满足安全要求是两回事，不能只凭理论公式结案。

### 24. 教学迁移题（新增练习，不属于历史考试）

给定：Global Path 无碰撞，但局部 Controller 每次进入同一转角都停住。应检查哪些证据、为什么不能只重启 Planner？  
**参考检查：** 当前姿态与 Footprint、转角曲率和控制速度限制、局部 Costmap、Controller 采样/评分结果、速度反馈、底盘真实响应、路径版本；在这些资料未对齐前不能确定故障归因。

## Mastered

- Path represents planned spatial route; Trajectory adds time, velocity and execution state.
