## 2. IMU：Gyroscope 与 Accelerometer

### Gyroscope

陀螺仪直接测角速度：

$$
\omega=[\omega_x,\omega_y,\omega_z]^T
$$

单位通常为 `rad/s`。它不直接测 orientation。

简单一维姿态由积分得到：

$$
\theta_{k+1}=\theta_k+\omega_k\Delta t
$$

因此：

```text
Gyro angular velocity
→ integration
→ orientation estimate
```

Gyro bias 会先造成 orientation error，再影响 gravity compensation，最终恶化 velocity / position。

### Accelerometer

加速度计不能简单理解为直接测 world-frame 线加速度。它更接近测 **specific force**，结果与 gravity、body frame、orientation、bias 都有关。

静止时 world-frame 线加速度可以是 0，但 accelerometer 某轴仍可能接近 `9.81 m/s²`。

位置链：

```text
specific force
→ gravity/orientation compensation
→ acceleration
→ integrate to velocity
→ integrate to position
```

因此 IMU 不直接测 position。

## 3. Encoder：最底层软件可读量与角度

以光电编码器为例：

```text
shaft rotation
→ light / dark transition
→ electrical pulse edges
→ tick / code
```

若一圈对应：

$$
N_{per\ rev}
$$

tick，则累计：

$$
N_{tick}
$$

对应转角：

$$
\Delta\phi=N_{tick}\frac{2\pi}{N_{per\ rev}}
$$

本质是：一整圈 $2\pi$ 被离散成固定份数。

常见 A/B 两相信号通过相位先后判断正反转；Z 相可提供每圈参考位置。

---

## 4. 电机轴、减速比与轮轴

若 encoder 在电机轴，必须考虑减速比：

$$
G=\frac{\theta_{motor}}{\theta_{wheel}}
$$

所以：

$$
\theta_{wheel}=\frac{\theta_{motor}}{G}
$$

不能直接把 motor angle 当 wheel angle。

---

## 5. Wheel Rotation → Distance → Odom Pose

轮半径为 $r$，轮子转角变化为 $\Delta\phi$：

$$
\Delta s=r\Delta\phi
$$

这是圆弧长度公式。

可直接由转角算等效滚动距离，也可以先算：

$$
\omega=\frac{\Delta\phi}{\Delta t},\qquad v=r\omega
$$

再积分得到位移。

差速底盘简化 yaw 变化：

$$
\Delta\psi=\frac{\Delta s_R-\Delta s_L}{b}
$$

其中 $b$ 是左右轮间距。

因此 `/wheel_odom.pose` 的链条是：

```text
encoder tick
→ motor angle
→ gear ratio
→ wheel angle
→ wheel distance
→ chassis kinematic model
→ Δx / Δy / Δyaw
→ integration
→ wheel odom pose
```

所以 wheel odom pose 不是 encoder 直接测出来的 robot pose。

### Wheel Slip

编码器可以完全正确地测到“轮子确实转了”，但如果轮子打滑：

```text
wheel rotation correct
≠ robot translation correct
```

错的是“纯滚动”等运动模型假设，而不一定是传感器本身。

## 6. LiDAR：Range、Beam、Intensity 与 XYZ

### Beam

Beam 是一束激光束。设备知道该束光的方向，例如：

- 水平方位角 $\theta$；
- 仰角 $\phi$。

再测距离 $r$，即可进行几何转换：

$$
x=r\cos\phi\cos\theta
$$

$$
y=r\cos\phi\sin\theta
$$

$$
z=r\sin\phi
$$

因此：

```text
range + beam direction
→ geometry
→ XYZ in LiDAR frame
```

XYZ首先通常属于 LiDAR 自身 frame，不自动等于 `base_link`。要变到机器人底盘坐标系，需要 LiDAR→base 的外参。

### ToF Range

最直观的 ToF 测距：

$$
r=\frac{c\Delta t}{2}
$$

因为光经历：

```text
LiDAR → object → LiDAR
```

总传播路程是 $2r$。

激光属于光，光属于电磁波的一部分。

### Intensity

Intensity 表示**该次回波被接收时的信号强弱**，不是点云密度，也不是“信息量”。

它会受：

- surface reflectivity；
- incidence angle；
- distance；
- surface roughness；
- emitter / receiver characteristics；
- rain / fog 等传播环境；

影响。

镜面反射不一定 intensity 高，因为光也可能被反射到接收器之外。

工程用途包括反光板、路面标线、匹配 / 配准辅助特征等。

## 7. Raw Measurement、Raw Cloud 与 PointCloud2

需要区分层级：

### 层 A：更接近底层物理测量

```text
optical/electrical response
→ ToF / phase / beam-related measurement
```

### 层 B：工程上常称 raw cloud

驱动已根据 range + beam geometry 转成：

```text
x, y, z, intensity, timestamp, ring/line...
```

它常被叫“原始点云”，但已经不是最底层光电数据。

### 层 C：进一步算法处理

可能又经过：

- transform；
- deskew；
- filtering；
- downsampling；
- scan merge；

再发布新的 `PointCloud2`。

比较两个点云 topic 时，应检查 `frame_id`、point fields、timestamp/per-point time、intensity/reflectivity、ring/line、deskew、filter、downsample、transform。

## 8. LiDAR Deskew：运动去畸变

LiDAR 的 deskew 不是相机镜头的径向 / 切向畸变。

一帧点云需要一段采集时间，其中各点测量时刻不同。如果机器人在这段时间运动，则这些点实际上对应不同 robot pose。

Deskew 的核心：

```text
different point timestamps
+ robot motion estimate
→ transform every point
→ same reference time / reference pose
```

即：

> 根据每个点的测量时间和机器人运动，把不同时间测得的点补偿到同一个参考时刻的位姿下。

Timestamp 说明“这个点什么时候测”；IMU / odom 等 motion estimate 说明“从该时刻到参考时刻机器人运动了多少”。两者缺一不可。

## 9. RGB Camera：直接得到什么

普通 RGB 图像可以写成：

$$
I(u,v)=(R,G,B)
$$

其中：

- $(u,v)$：二维 pixel index；
- $R,G,B$：该像素三个颜色通道的强度。

Camera 并不直接输出：

- `person`；
- object depth；
- 3D world coordinate；
- traversable area；

这些属于后续算法结果。

像素位置只是 image plane 上的位置，不等于空间 3D 坐标。

## 10. YOLO 与 Learned Depth 的位置

YOLO：

```text
RGB image
→ neural network learned visual features
→ bbox / class / confidence
```

这里的 feature 不是线性代数里的 eigenvalue。现代 YOLO 的视觉特征主要由训练学习，不是先手工算 SIFT / HOG / ORB 描述子再分类。

单目深度：

```text
RGB
→ learned visual priors
→ estimated depth
```

属于算法估计，不是 Camera 硬件物理测距。

典型限制：

- scale ambiguity；
- generalization / distribution shift；
- transparent / reflective / mirror surfaces；
- RGB appearance 与第一个真实物理表面不一致。

其中“新环境错误”通常属于泛化不足的具体表现，而尺度歧义属于单目几何本身的信息不足，两者不是同一类问题。

## 11. Stereo / Structured Light / ToF 的基本位置

本日只建立传感器类别边界，完整 Camera geometry 留 M05 Day22–25。

### Stereo

```text
two cameras
+ known baseline
+ same 3D point correspondence
+ disparity
→ triangulation
→ depth
```

视差是同一个 3D 点在左右图中的**像素位置差**，不是物体大小差。

经典关系：

$$
Z=\frac{fB}{d}
$$

完整推导与 intrinsic 留 Day25。

### Structured Light

```text
known projector pattern
+ camera correspondence
+ known projector-camera baseline
→ triangulation
→ depth
```

它不是 ToF，不通过 `c × time` 测距。

### ToF Camera

通过光传播的飞行时间或调制相位获得距离 / depth，与单目神经网络的 learned depth 本质不同。

## 13. 今日掌握情况

### Mastered

- gyro 直接测 angular velocity，不直接测 orientation；
- accelerometer 不是简单 world-frame acceleration；
- encoder tick → angle → wheel displacement → odom pose 的完整链；
- gear ratio 与 wheel angle 的关系；
- wheel slip 是 model assumption failure，不必然是 encoder failure；
- LiDAR range + beam angle → LiDAR-frame XYZ；
- LiDAR XYZ 不自动是 `base_link`；
- ToF range 的往返传播逻辑；
- intensity 是回波强度，不是点密度；
- raw optical measurement / raw cloud / processed point cloud 的层级区别；
- deskew 是不同测量时刻 → 运动补偿 → 同一参考时刻；
- RGB Camera 直接测 image / pixel intensity，不直接测 semantic / 3D；
- YOLO / monocular depth 属于算法推导；
- stereo disparity 是左右图同一点的 pixel position difference；
- Stereo / Structured Light / ToF 的基本原理边界；
- FAST-LIO pose 是 estimated state，不是几何坐标转换。

### Corrected

1. 曾把 motor / wheel 差异主要归因于“半径不同”；纠正为 software chain 中应明确 gear ratio。
2. 差速底盘示例将 `0.2 / 0.5` 算成 `4 rad`；纠正为 `0.4 rad`。
3. 曾把 LiDAR XYZ 默认理解成 base_link；纠正为先属于 LiDAR frame，再由 extrinsic 转换。
4. 曾把 intensity 理解成点云聚集程度；纠正为单次回波信号强度。
5. 曾把 deskew 理解成“按时间分类”；纠正为每点按 timestamp + motion compensation 统一到同一参考时刻。
6. 曾把 YOLO feature 与 descriptor / eigenvalue 混淆；纠正为 neural network learned visual feature。
7. 曾把 disparity 理解成左右图物体大小差；纠正为同一3D点左右 pixel position difference。
8. 曾把 Structured Light 与 ToF 混淆；纠正为 Projector + Camera + triangulation。
9. 曾把 LiDAR XYZ 与 Stereo 原理混淆；定向复测后已能区分：LiDAR `range + beam → XYZ`；Stereo `baseline + disparity → depth`。
