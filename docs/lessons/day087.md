# Part A — Foundation（基础层）

## 1. Critic 是什么？

Critic 是一个轨迹评价函数。它接收本轮状态、候选轨迹、参考路径、costmap 等信息，对候选轨迹的某个行为属性打分。

例如：

- 离参考路径有多远；
- 是否朝目标前进；
- 是否接近障碍物；
- 是否发生碰撞；
- 是否过度倒车；
- 是否持续原地旋转；
- 控制变化是否过于剧烈。

Critic 不直接决定电机转速，也不直接发布底盘命令。它提供代价，影响候选轨迹的总 Cost，进而影响 MPPI 权重和控制序列更新。

## 2. 先分清两类 Weight

这里有两种不同的权重，不能混为一谈。

**第一类：Critic Weight（评价项权重）**

记为 \(a_i\)，表示第 i 个 Critic 在总 Cost 中的影响系数。

模块教学契约中的写法是 \(S_k=\sum_i w_iC_{i,k}\)。为避免与 MPPI 候选样本权重混淆，本讲义将 Critic Weight 记为 \(a_i\)，将 MPPI Sample Weight 记为 \(p_k\)；因此这里的 \(a_i\) 与契约公式中的 \(w_i\) 是同一个量。

**第二类：MPPI Sample Weight（候选样本权重）**

记为 \(p_k\)，表示第 k 条候选控制序列在 MPPI 加权更新中的权重。

\[
a_i:\text{第 i 个评价项的影响程度}
\]

\[
p_k:\text{第 k 条候选轨迹对控制更新的贡献}
\]

Critic Weight 先影响轨迹 Cost；轨迹 Cost 再影响 MPPI Sample Weight。

## 3. 总 Cost 的基本构成

对第 k 条候选轨迹，设第 i 个 Critic 的原始代价为 \(C_{i,k}\)，其评价项权重为 \(a_i\)。

本课程先使用简化表达：

\[
\boxed{
S_k=\sum_{i=1}^{M}a_iC_{i,k}
}
\]

其中：

- \(k\)：候选轨迹编号；
- \(i\)：Critic 编号；
- \(M\)：参与评价的 Critic 数量；
- \(C_{i,k}\)：第 k 条轨迹在第 i 个评价项上的原始 Cost；
- \(a_i\)：第 i 个评价项的权重；
- \(S_k\)：第 k 条轨迹的总 Cost。

这是理解多项代价如何合成的基础模型。具体实现可能包含 cost_power、阈值、时间聚合、归一化或额外修正项，不能假定所有 Critic 都严格执行一个简单乘法。

## 4. Critic 的原始 Cost 如何沿预测时域计算？

Critic 评价的是一整条候选轨迹，而不一定只评价最后一个预测点。

可以把第 i 个评价项在第 t 个预测点的局部代价写成：

\[
c_i(x_{k,t},u_{k,t})
\]

然后通过某种聚合方式形成轨迹级代价：

\[
C_{i,k}=
\mathcal A_t\left[c_i(x_{k,t},u_{k,t})\right]
\]

\(\mathcal A_t\) 可能是求和、均值、取末端值、采样点平均或其他实现特定的计算方式。

**注意：不同 Critic 的时间聚合方式可能不同。** 不能看到一个 Critic 的公式是 mean，就认为其他 Critic 也一定是 mean。

## 5. Path Distance / Path Follow：评价离参考路径有多远

参考路径是几何路径。候选轨迹可能在预测过程中偏离参考路径。

对候选轨迹位置 \(p_{k,t}=[x_{k,t},y_{k,t}]^T\)，可以定义到参考路径 P 的最近距离：

\[
d_{\mathrm{path}}(p_{k,t})
=
\min_{q\in P}\|p_{k,t}-q\|
\]

一个简化的路径距离代价可以是：

\[
C_{\mathrm{path},k}
=
\sum_t d_{\mathrm{path}}(p_{k,t})
\]

它会惩罚偏离参考路径的候选轨迹。

但路径跟随不一定要求每个点都贴着路径。面对动态障碍物，允许适当偏离，可能比强行贴线更合理。

## 6. Path Align：评价轨迹是否沿着路径意图前进

Path Follow 与 Path Align 相关，但不完全相同。

- Path Follow 更关注是否沿路径取得进展、是否接近路径上的目标点；
- Path Align 更关注轨迹是否与参考路径保持空间或方向上的一致。

一种简化的对齐代价：

\[
C_{\mathrm{align},k}
=
\frac{1}{N_a}
\sum_{j=1}^{N_a}
\|p_{k,t_j}-q_j\|
\]

如果还考虑路径方向，可以增加航向误差：

\[
e_{\psi,j}
=
\operatorname{wrap}(\psi_{k,t_j}-\psi_{P,j})
\]

再构造：

\[
C_{\mathrm{align},k}
=
\frac{1}{N_a}
\sum_j
\left(
\|p_{k,t_j}-q_j\|
+\beta |e_{\psi,j}|
\right)
\]

这是概念性表达。Nav2 Humble 的 PathAlignCritic 是否把路径朝向加入计算，由 use_path_orientations 等配置决定。

## 7. Goal Critic：评价是否接近目标

目标位置代价可以写成：

\[
C_{\mathrm{goal},k}
=
\|p_{k,N}-p_g\|
\]

目标朝向代价可以写成：

\[
C_{\mathrm{goal\_yaw},k}
=
\left|
\operatorname{wrap}(\psi_{k,N}-\psi_g)
\right|
\]

实际实现也可能对多个预测点求均值，或只在距离目标进入某个阈值后启用。

因此要区分：

- 目标位置；
- 目标朝向；
- 是否进入 Critic 的激活范围。

## 8. Obstacle Critic：评价与障碍物的关系

障碍代价通常不只是判断“撞了还是没撞”，还会考虑机器人与障碍物的距离。

可以将预测点到障碍物的有效距离写成：

\[
d_{k,t}
\]

一种简化的排斥代价：

\[
c_{\mathrm{obs}}(d_{k,t})
=
\max(0,d_{\mathrm{rep}}-d_{k,t})
\]

当距离越小，代价越大。

实际实现可能使用：

- Costmap 的障碍代价值；
- Inflation Layer 的距离衰减；
- 机器人 footprint；
- 近碰撞阈值；
- 独立的碰撞代价。

Costmap 数值不一定直接等于米制距离。不能把 costmap cost 当作真实距离使用，除非实现明确完成了相应转换。

## 9. Footprint：为什么不能只检查机器人中心点？

机器人不是一个没有尺寸的点。

如果只检查中心点，中心点没有进入障碍物，仍然可能发生：

- 机器人侧面擦墙；
- 转弯时后角扫到障碍；
- 机器人前端或外侧进入障碍区域。

因此碰撞评价应结合机器人 footprint 和姿态：

\[
\mathcal F(x,y,\psi)
\]

候选轨迹在每个预测姿态都可能需要进行 footprint 碰撞检查。

对非圆形机器人，转弯时 footprint 随 yaw 改变。只用一个固定半径近似，可能过于保守，也可能不够安全，取决于几何形状和使用方式。

## 10. Velocity Preference：评价速度是否符合运动偏好

速度偏好不一定是“速度越快越好”。

可以定义目标速度 \(v^*\)，用一个简化代价表示：

\[
C_v=(v-v^*)^2
\]

也可以根据场景偏好：

- 更倾向于向前而不是倒车；
- 不希望速度长期落在电机死区；
- 不希望在狭窄区域保持过高速度；
- 允许在障碍物附近主动降低速度。

Nav2 Humble 有 PreferForwardCritic 和 VelocityDeadbandCritic 等具体实现。它们不等于一个通用的目标速度跟踪 Critic。

## 11. Smoothness / Acceleration / Jerk：评价控制变化是否平顺

对离散控制序列：

\[
u_t=
\begin{bmatrix}
v_t\\
\omega_t
\end{bmatrix}
\]

控制变化量：

\[
\Delta u_t=u_t-u_{t-1}
\]

线速度加速度近似：

\[
a_t=\frac{v_t-v_{t-1}}{\Delta t}
\]

加加速度（jerk）近似：

\[
j_t=\frac{a_t-a_{t-1}}{\Delta t}
\]

可以构造：

\[
C_{\mathrm{smooth}}
=
\sum_t\|\Delta u_t\|^2
\]

\[
C_{\mathrm{acc}}
=
\sum_t\|a_t\|^2
\]

\[
C_{\mathrm{jerk}}
=
\sum_t\|j_t\|^2
\]

这些代价用于惩罚速度或控制变化过于剧烈。

但必须明确：并不是所有 MPPI 实现都内置了 acceleration / jerk Critic。Nav2 Humble 的 TwirlingCritic 主要惩罚角速度幅值，不等于完整的加速度和 jerk 约束。

## 12. Weighted Contribution：真正影响总 Cost 的是加权贡献

只看 Critic Weight 不够，也不能只看 Raw Cost。

简化模型下，第 i 项对第 k 条轨迹的贡献是：

\[
\boxed{
D_{i,k}=a_iC_{i,k}
}
\]

例如：

| Critic | Raw Cost | Weight | Weighted Contribution |
|---|---:|---:|---:|
| Path Align | 0.2 | 10 | 2.0 |
| Obstacle | 0.5 | 20 | 10.0 |
| Goal | 1.0 | 3 | 3.0 |
| Smoothness | 2.0 | 1 | 2.0 |

总 Cost：

\[
S_k=2+10+3+2=17
\]

本例中 Obstacle 项贡献最大。

但不能据此说 Obstacle 的 weight 最大就一定主导所有轨迹。不同候选轨迹的 Raw Cost 不同，必须逐条分析。

## 13. Cost Power：代价权重不一定只是简单相乘

一些实现还提供 cost_power：

\[
\tilde C_{i,k}
=
(a_iC_{i,k})^{p_i}
\]

当 \(p_i>1\) 时，大代价会被进一步放大，小代价与大代价之间的差距也可能改变。

具体 Critic 还可能先对时间维度求和或均值，再乘权重和取幂。

所以实际源码分析必须找到每个 Critic 的 score()，不能只看 YAML 里的 cost_weight。

## 14. Scale / Normalization：不同代价必须放在可比较的尺度上

不同 Raw Cost 的量纲和数值范围可能完全不同：

| 代价 | 可能的量纲或数值尺度 |
|---|---|
| 路径距离 | m |
| 航向误差 | rad |
| 线速度偏差 | m/s |
| 加速度 | m/s² |
| jerk | m/s³ |
| Costmap | 代价值，不是米 |
| 碰撞惩罚 | 人为设定的数值 |

如果一个 Critic 的 Raw Cost 数值远大于其他项，即使它的 weight 较小，也可能主导总 Cost。

因此需要检查：

1. Raw Cost 的定义和数值范围；
2. 是否做了时间求和、均值或归一化；
3. weight 是否把不同量纲的项调整到合理的相对尺度；
4. cost_power 是否进一步放大大值；
5. 是否存在阈值或近目标时的停用逻辑。

**MPPI 的样本权重归一化，不等于 Critic 之间已经完成尺度归一化。**

样本权重：

\[
\sum_k p_k=1
\]

它只说明不同候选轨迹的权重被归一化，不会自动让 Path、Obstacle、Goal 的 Raw Cost 变得可比较。

# Part B — Core Theory（核心理论层）

## 15. 多个 Critic 如何形成 trade-off？

一个候选轨迹可能：

- 更贴近 Path，但更靠近障碍物；
- 更远离障碍物，但偏离 Path；
- 更快接近 Goal，但控制变化更剧烈；
- 更平滑，但进展速度较慢。

MPPI 通过总 Cost 比较这些候选方案。

假设两个候选轨迹，权重为：

\[
a_{\mathrm{path}}=4,\quad
a_{\mathrm{obs}}=8,\quad
a_{\mathrm{goal}}=2,\quad
a_{\mathrm{smooth}}=1
\]

所有 Raw Cost 都是本例中归一化后的示意数值。

候选 A：贴近路径，但更靠近障碍物。

\[
C_A=[0.2,\ 2.0,\ 0.3,\ 0.1]
\]

\[
S_A=4(0.2)+8(2.0)+2(0.3)+1(0.1)
=17.5
\]

候选 B：适当绕开障碍物，但偏离路径更多。

\[
C_B=[1.0,\ 0.2,\ 0.5,\ 0.4]
\]

\[
S_B=4(1.0)+8(0.2)+2(0.5)+1(0.4)
=7.0
\]

因此：

\[
S_B<S_A
\]

候选 B 的总 Cost 更低。

这说明 MPPI 不会因为候选 B 偏离路径就必然拒绝它；只要障碍物代价下降带来的收益足够大，绕行候选仍可能占优。

## 16. Soft Constraint 与 Hard Constraint

**Soft Constraint（软约束）**

违反偏好或接近边界时增加代价：

\[
S_k\leftarrow S_k+C_{\mathrm{penalty}}
\]

它允许不同目标之间进行 trade-off。

例如：

- 偏离路径增加代价；
- 靠近障碍物增加代价；
- 速度不符合偏好增加代价；
- 控制变化太剧烈增加代价。

软约束的本质是：允许违反，但付出代价。

**Hard Constraint（硬约束）**

不允许进入不可行集合：

\[
x_{k,t}\in\mathcal X_{\mathrm{feasible}}
\]

\[
u_{k,t}\in\mathcal U_{\mathrm{feasible}}
\]

违反后，候选应被拒绝、判为不可行，或由独立安全机制阻止执行。

硬约束的本质是：不允许违反，而不是“违反了就多扣一点分”。

## 17. 为什么碰撞不能只是一个普通小 Penalty？

假设某条轨迹会碰撞，但它：

- 很贴近 Path；
- 很快接近 Goal；
- 速度变化很平滑。

如果碰撞代价只是一个小数值，那么其他 Critic 的收益可能抵消碰撞惩罚，最终碰撞轨迹仍可能得到较低总 Cost。

因此碰撞不能作为普通的小惩罚项处理。

应根据系统安全设计采取一种或多种措施：

1. 将碰撞状态判为不可行；
2. 对碰撞候选设置足够大的惩罚，并明确无可行候选时的 fallback；
3. 对最终速度命令增加独立安全检查；
4. 当状态或环境信息不可信时进入安全降级，而不是继续优化并假定环境有效。

**注意：有限的大惩罚仍然不是数学意义上的硬约束。** 如果系统仅使用有限数值，必须检查其在所有候选和 fallback 情况下的行为。

## 18. Slow Band / Hard-brake Band：近障碍时如何改变行为？

可以按有效障碍距离设计分区。下面是一个通用设计思路，不是 Nav2 Humble 固定提供的统一三段式参数。

- **正常区域：** 障碍距离充足，正常考虑路径进展和速度偏好。
- **减速区域（Slow Band）：** 距离开始接近安全阈值，提高低速候选的相对优势，降低高速候选的优势。
- **制动区域（Hard-brake Band）：** 预测距离已经不足以安全停止时，不能只增加一个小 penalty；应触发硬速度限制、拒绝危险轨迹或独立安全制动。

如果只有 Soft Cost，MPPI 可能为了路径进展或目标接近而选择继续前进。

因此 Hard-brake Band 必须有明确的安全触发逻辑，不能只依赖“把 obstacle weight 调大”。

## 19. Footprint / State Error / Stopping Distance / Latency 如何共同决定 Safety Margin？

机器人是否安全，不能只看中心点到障碍物的距离。

一个简化的一维保守安全距离模型：

\[
\boxed{
d_{\mathrm{required}}
=
r_{\mathrm{footprint}}
+e_{\mathrm{state}}
+v_{\mathrm{rel}}T_{\mathrm{latency}}
+\frac{v_{\mathrm{rel}}^2}{2a_{\mathrm{brake}}}
+m
}
\]

其中：

- \(r_{\mathrm{footprint}}\)：机器人沿障碍物接近方向的有效外形尺寸；
- \(e_{\mathrm{state}}\)：位置和姿态估计误差折算出的保守距离；
- \(v_{\mathrm{rel}}\)：机器人与障碍物之间的接近速度；
- \(T_{\mathrm{latency}}\)：感知、状态估计、规划、控制、通信和执行器响应的总延迟；
- \(a_{\mathrm{brake}}\)：实测可保证的有效制动减速度；
- \(m\)：额外安全余量。

延迟期间的接近距离：

\[
d_{\mathrm{latency}}=v_{\mathrm{rel}}T_{\mathrm{latency}}
\]

理想恒定减速度下的制动距离：

\[
d_{\mathrm{brake}}
=
\frac{v_{\mathrm{rel}}^2}{2a_{\mathrm{brake}}}
\]

例如速度增加一倍，理想制动距离会增加到四倍。

如果位置误差可用标准差 \(\sigma_p\) 描述，可以在指定置信水平下考虑 \(k\sigma_p\) 的保守误差项；但具体 k 值需要由系统风险要求决定。

**适用边界：** 这个公式是一维近似，不是完整安全认证模型。它假设接近速度和制动减速度可用常数近似；坡度、地面摩擦、轮胎打滑、制动建立时间、机器人转动时 footprint 扫掠、动态障碍物运动等都可能改变结果。实际 \(a_{\mathrm{brake}}\) 应来自保守实测，而不是直接使用电机标称值。

## 20. Critic Conflict：多个评价目标为什么会互相打架？

典型冲突：

| Critic A | Critic B | 可能的冲突 |
|---|---|---|
| Path Align | Obstacle | 贴路径与绕开动态障碍物冲突 |
| Path Follow | Smoothness | 快速取得进展与平滑控制冲突 |
| Goal Angle | Prefer Forward | 目标朝向与向前行驶偏好冲突 |
| Velocity Preference | Obstacle / Braking | 保持速度与近障减速冲突 |
| Goal | Path Align | 直接接近目标与继续贴合原路径冲突 |

冲突不意味着某个 Critic 一定写错了。

它可能是多个目标本来就存在 trade-off；真正的问题在于：

- 代价尺度不合理；
- weight 不合适；
- 激活阈值不合理；
- 某个 Critic 没有在应当停用时停用；
- 硬安全边界被错误地实现成普通软代价。

## 21. Path Align 与 Obstacle 的配合

如果 Path Align 权重过高，候选轨迹可能不愿意离开原路径，即使前方有动态障碍物。

如果 Obstacle 影响过强，候选轨迹可能过早远离路径，造成绕行过大。

因此不能只调一个 weight。

需要同时检查：

- Path Align 的 Raw Cost 与加权贡献；
- Obstacle 的 Raw Cost 与加权贡献；
- footprint 检查是否符合机器人真实外形；
- inflation 参数是否合理；
- Path Align 是否受动态障碍物占用比例和阈值影响；
- Path Follow 是否仍在驱动合理的路径进展。

Nav2 Humble 的 PathAlignCritic 会检查局部路径点有效性；当路径被动态障碍物阻塞到一定比例时，它会停止施加该项代价，让障碍物评价接管这一部分。具体阈值由参数决定。

## 22. 从 Robot Behavior 反推 Critic 的证据链

看到机器人行为异常时，不要先猜哪个 weight 错了。

应建立完整证据链：

\[
\boxed{
\begin{aligned}
&\text{Observed Behavior}\\
\rightarrow\;&\text{Candidate Trajectories}\\
\rightarrow\;&\text{Raw Critic Costs}\\
\rightarrow\;&\text{Weighted Contributions}\\
\rightarrow\;&\text{Total Cost}\\
\rightarrow\;&\text{MPPI Sample Weights}\\
\rightarrow\;&\text{Weighted Perturbation}\\
\rightarrow\;&\text{Updated Nominal}\\
\rightarrow\;&\text{Clipping / Smoothing}\\
\rightarrow\;&\text{Command and Actual Motion}
\end{aligned}
}
\]

每一步都要有对应证据。

只看最终 cmd_vel，无法知道是哪个 Critic 主导了选择。

只看 YAML 的 cost_weight，也无法知道该项在当前候选轨迹上实际贡献了多少。

## 23. 行为一：提前绕障

现象：障碍物还没有真正挡住当前路径，机器人就提前向侧面绕行。

优先检查：

1. Obstacle Raw Cost 是否在较远距离就明显增加；
2. Inflation Layer 的影响范围是否过大；
3. footprint 是否正确，是否把机器人外形重复放大；
4. critical / repulsion 两类代价是否被混淆；
5. Path Align / Path Follow 是否与 Obstacle 存在明显权重差异；
6. 高权重候选是否已经明显向侧面偏移。

不能仅凭“提前绕”就断言 obstacle weight 太高。必须看候选轨迹与加权贡献。

## 24. 行为二：绕开障碍物后又被拉回原路径

现象：机器人先绕开障碍物，绕过后又明显向原路径回拉。

可能涉及：

- Path Align 重新开始对绕行轨迹施加较大代价；
- Path Follow 选择的目标路径点不合理；
- 动态障碍物消失后，路径有效性发生变化；
- 当前 path 或 path identity 已经改变；
- 障碍物代价下降，但路径对齐代价迅速占主导。

应对照绕行前、绕行中、绕行后的同一组 Critic 数据，重点看：

\[
D_{\mathrm{path},k},\quad
D_{\mathrm{obstacle},k},\quad
S_k,\quad p_k
\]

并检查 Path Follow 的目标点索引和 Path Align 的激活条件。

## 25. 行为三：左右互搏

现象：机器人左右摆动、反复改变绕障方向，或者候选方向在相邻周期之间频繁切换。

可能的代价层原因：

- 左绕与右绕候选的总 Cost 很接近；
- Obstacle 与 Path Align 的相对贡献在不同周期反复变化；
- Path Angle / Goal Angle 对航向的偏好与障碍代价冲突；
- Critic 激活阈值或目标点索引发生跳变；
- 权重集中在方向相反的候选之间，导致更新方向不稳定。

但不能只凭左右摆动就认定是 Critic 冲突。还要排除 Day88 将深入的反馈延迟、状态时间戳、速度限幅、模型失配和执行器响应问题。

## 26. Nav2 Humble：Critic Plugin 如何组织？

在 Nav2 Humble 中：

- 配置中的 critics 列表指定需要加载的 Critic；
- CriticManager 通过 pluginlib 加载对应插件；
- 每个 Critic 实现自己的 score(CriticData & data)；
- CriticManager 依次调用这些 score()；
- Critic 通过 data.costs 累加对候选轨迹的评价。

CriticData 中包含：

- 当前 state；
- 候选 trajectories；
- path；
- 每条候选轨迹的 costs；
- model_dt；
- fail_flag；
- motion_model；
- path validity 等共享信息。

## 28. Nav2 Humble：必须分清 Critic Penalty 与实际控制约束

一个容易误解的地方是：名字叫 ConstraintCritic，不代表它本身就是完整的硬约束。

在 Humble 源码中：

1. ConstraintCritic 计算超出最大 / 最小速度范围的量，并把相应代价累加到 data.costs。
2. Optimizer 的 applyControlSequenceConstraints() 另行对控制序列执行 vx、wz 等限幅，再调用 motion model 的 applyConstraints()。
3. ObstaclesCritic / CostCritic 对碰撞候选赋予有限碰撞代价；当所有候选轨迹都发生碰撞时，设置 fail_flag。
4. Optimizer 检测 fail_flag 后进入 fallback，reset 并重试；超过 retry_attempt_limit 后报错。

因此：

- ConstraintCritic 的代价项是评价机制；
- 控制序列 clipping 是输入边界处理；
- 碰撞代价与全体候选失败处理是另一条机制；
- 它们不能被统称为一个普通的“硬约束”。

特别注意：给碰撞一个很大的有限 Cost，并不等价于从数学上彻底排除所有碰撞候选；也不代表真实机器人已经具备独立的安全制动能力。

## 29. Owner：如何做 Critic Attribution 与调参？

建议为每个候选轨迹记录：

| 日志字段 | 目的 |
|---|---|
| candidate_id | 关联同一条候选轨迹 |
| trajectory / min_clearance | 观察候选行为与最近障碍距离 |
| raw_cost_i | 每个 Critic 的原始代价 |
| critic_weight_i / cost_power_i | 评价项配置 |
| weighted_contribution_i | 每个 Critic 的实际加权贡献 |
| total_cost | 候选轨迹总 Cost |
| normalized_sample_weight | MPPI 样本权重 |
| weighted_perturbation | 候选扰动对控制更新的贡献 |
| nominal_before / nominal_after | 观察更新前后控制序列 |
| clipped_before / clipped_after | 判断限幅改变了什么 |
| published_command / actual_feedback | 区分控制输出与真实执行 |

推荐排查顺序：

1. 复现同一场景，固定 path、costmap、footprint 和参数。
2. 确认异常行为对应哪些候选轨迹。
3. 查看每条轨迹的各 Critic Raw Cost。
4. 计算各项 Weighted Contribution，而不是只比较 weight。
5. 求和得到 Total Cost，核对 MPPI Sample Weight。
6. 查看高权重候选的方向和扰动如何共同改变 nominal sequence。
7. 检查 control clipping、smoothing 和最终发布命令。
8. 对照实际速度反馈、位姿与时间戳，判断是否是下游执行问题。

调参原则：

- 先确认 Raw Cost 定义、单位、聚合方式和数值尺度；
- 再调整 Critic Weight；
- 同时核对 cost_power、阈值、激活区间、footprint 和 inflation；
- 一次只调整一组有明确假设的参数；
- 用同一场景做前后对比，保留每个 Critic 的贡献日志。

不要看到“提前绕”就直接减小 Obstacle Weight，也不要看到“绕后回拉”就直接减小 PathAlign Weight。先用贡献数据确认是谁在主导行为。
