# 09｜高级插件体系与系统定制化设计

## 定位

本目录虽然名称仍为 `plugins_and_customization`，但实际内容不再是“把插件接进去”这么浅，而是进入高级插件体系与系统定制化的设计层。

目标不是“能用某个扩展点”，而是逐步具备：

- plugin family 全景理解
- planner / controller / BT / behavior / costmap layer 等扩展点对比能力
- 插件接口、可维护性、性能、扩展性权衡能力
- 中等复杂度改造与小范围原创扩展能力
- 从单点扩展走向系统定制化组合能力

## 为什么这个模块必须存在

在 05 模块已经进入过：

- 最小插件接入
- 小范围改造
- server / plugin / config 挂接理解

在 08 模块会进一步建立：

- 大代码库阅读方法
- 架构地图
- 调用链与接口识别能力

这时如果还停留在“接一个插件跑起来”，就会明显不够。  
要继续往核心层推进，必须补上：

- 插件体系全景
- 扩展点设计比较
- 定制化系统组合
- 原创扩展的最小实践

## 模块目标

完成本模块后，应逐步具备以下能力：

- 能说清不同插件族的职责、边界和使用场景
- 能分析插件接口设计的优点、缺点和约束
- 能说明插件对性能、资源和维护成本的影响
- 能完成中等复杂度插件改造
- 能尝试小范围原创扩展，而不是只复制已有实现

## 模块主要产物

本模块后续应重点沉淀：

- 插件族谱图
- 扩展点设计比较表
- 插件装载链与参数挂接深化文档
- 插件性能与资源影响分析
- 中等复杂度插件改造记录
- 小范围原创扩展雏形
- 系统定制化设计说明
- 模块总结
- 模块总验收
- 证据索引

## 学习与执行方式

本模块采用 Sprint 机制推进，每个 Sprint 按以下节奏执行：

1. 问题定义与插件体系图谱建立  
2. 运行时证据与装载链证据采集  
3. 插件接口、实现与设计资料深读  
4. 中等复杂度改造、对照实验或原创小扩展  
5. 总结、闭卷与复盘  

每天必须保留：

- 今天进入的是哪一类插件体系
- 今天识别的接口、抽象和装载关系
- 今天的改造或实验动作
- 今天最容易混淆的概念
- 当天闭卷问答
- 明日衔接点

## 验收标准

完成本模块时，至少应满足以下条件：

- 能说清 planner / controller / BT / behavior / layer 等插件体系差异
- 能分析插件设计的性能与维护性影响
- 能完成一个中等复杂度插件改造或系统定制化方案
- 能形成至少一个原创小扩展雏形
- 能通过闭卷稳定表达“为什么这个扩展点值得这样设计”

## 与后续模块的关系

本模块直接连接研究层：

- 为 `10｜文献矩阵、baseline 地图、论文复现与 benchmark 建立` 提供“真实系统上的可扩展实现底座”
- 为 `11｜原创方法、实验叙事与论文管线` 提供原创方法的系统着陆点
- 也是“从会改代码走向会设计系统”的关键一跳
