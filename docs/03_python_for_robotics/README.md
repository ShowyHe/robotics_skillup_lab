# 03｜实验基础设施与工程脚本体系

## 定位

本目录虽然名称仍为 `python_for_robotics`，但实际内容不再是通用 Python 语法训练，而是面向机器人系统开发与研究实验的工程级 Python 基础设施构建。

目标不是“会写几个脚本”，而是让 Python 真正承担以下角色：

- 实验编排
- 配置管理
- 日志与结果处理
- baseline / replay / regression 流程支撑
- 图表生成
- 可复现实验的工具底座

## 为什么这个模块必须存在

当前已经具备：

- `scripts/`
- `logs/`
- `results/`
- `configs/`
- `bags/`
- 按阶段文档化记录的能力

这说明已经不缺“能写点脚本”的能力，缺的是把这些脚本和目录提升成统一的实验基础设施。

如果这一步不做，会出现下面这些问题：

- 每次实验都靠手工拼步骤
- 结果目录结构不统一，后面很难复盘
- 参数 sweep、baseline 对照、结果归档效率低
- 脚本可运行，但不可维护、不可复用、不可扩展
- 做源码改造和论文实验时，底座不稳，整个效率会被拉垮

## 模块目标

完成本模块后，应逐步具备以下能力：

- 能设计带清晰输入输出的工程脚本，而不是一次性脚本
- 能统一管理配置、实验目录、日志与结果
- 能完成批量运行、结果汇总和图表生成
- 能为 replay、regression、baseline、ablation 等流程提供工具层支持
- 能把 Python 从“辅助工具”提升为“实验基础设施”

## 模块主要产物

本模块后续应重点沉淀：

- 工程脚本设计模板
- 配置与结果目录规范
- 批量运行与实验编排工具
- 结果解析与自动图表工具
- “Python 如何服务研究与工程”的说明文档
- 模块总结
- 模块总验收
- 证据索引

## 学习与执行方式

本模块采用 Sprint 机制推进，每个 Sprint 按以下节奏执行：

1. 问题定义与图谱建立  
2. 真实脚本与实验数据证据采集  
3. 配置、脚本、工具层深读与重构  
4. 编排、解析、归档、图表等动作  
5. 总结、闭卷与复盘  

每天必须保留：

- 今天要支撑的实验或工程问题
- 今天处理的配置 / 日志 / 结果 / 图表对象
- 今天脚本设计上的取舍
- 今天最容易混淆的概念
- 当天闭卷问答
- 明日衔接点

## 验收标准

完成本模块时，至少应满足以下条件：

- 脚本具备清晰输入输出、日志、异常处理与目录结构
- 能支撑批量实验和结果归档，而不是人工拷来拷去
- 能自动生成可用于对比和复盘的结果表与图
- 能把 Python 工具层直接服务于后续源码改造、benchmark 和论文实验
- 能通过闭卷稳定表达“为什么这样设计脚本和目录”

## 与后续模块的关系

本模块是后面很多高阶模块的底座：

- 为 `05｜Nav2 源码入口、改造与扩展点` 提供实验与验证工具层
- 为 `06｜评测科学、性能分析与研究实验纪律` 提供 benchmark / regression / replay 编排支撑
- 为后续 10–11 的 baseline 复现与论文实验提供基础设施
